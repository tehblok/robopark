# Кэши, ресурсы, PWA и OTA rc.34

Задача: конечный аудит после подготовки помощника, исправления доказанных
дефектов и OTA для Khadas. Исходная точка — `b5cd711c`, rc.33. Пакет пользователь
устанавливает отдельно; рабочий хост в рамках этого аудита не изменялся.

## Исправления

| Область | Подтверждённая проблема | Исправление и проверка |
| --- | --- | --- |
| AI worker на Khadas | Новые chat workers опрашивали БД каждые 250 мс даже на неподдерживаемом хосте | После восстановления прерванных заданий ожидать поддержки хоста без polling очереди; воспроизводящий тест стал зелёным |
| React resource cache | Ответ после `enabled=false` повторно сохранял защищённые данные | Смена `enabled` отзывает поколение владельца запроса; регрессионный тест |
| Страница помощника | Создание диалога/отправка сообщения продолжали HTTP-запрос после ухода со страницы | AbortSignal до HTTP-клиента; проверка отмены при unmount. Принятые сервером durable jobs сохраняются |
| Каталог парков | Повторное монтирование/уход не отменяли загрузку каталога | AbortController и cleanup, сохранены проверки поколения и области доступа |
| Unix AI broker | Пустые, недописанные и idle keep-alive соединения навсегда занимали ограниченные handler slots | 15 с бездействия сокета; закрытие timed-out buffered reader; четыре сценария воспроизведены до исправления и проходят после |

Независимое ревью этих изменений не выявило воспроизводимых регрессий.
Общий coalesced resource loader не получил физическую отмену общего запроса:
запрос может обслуживать нескольких потребителей. Исправлена именно запись
позднего результата; точечная отмена сети добавлена там, где владелец один.

## PWA и границы кэшей

Проверены существующие version/content-digest service worker caches, precache
ленивых маршрутов, удаление старых ресурсов при безопасной активации,
ограничение IndexedDB и восстановление её схемы, отсутствие API/вложений в SW
cache, защита очереди офлайн-действий и медиа при обновлении открытых клиентов.
Нового доказанного дефекта в этих механизмах не найдено.

## Снимок рабочего Khadas

Read-only SSH с проверкой сохранённого host key: aarch64, Linux 5.15.137,
около 5,6 GiB MemAvailable, swap не используется, корневой eMMC 51% (14 GiB
свободно), load average около 0,5. Опубликованный service worker сообщает rc.33.
Это моментальный снимок, не тест роста памяти. Среди failed systemd units
показана только системная `camera_isp_3a_server.service`; её настройки не менялись.

## Проверки исходников

- Полный API-прогон (включая `load`): 2 897 passed, 31 skipped, один сбой.
  Его единственная причина — устаревшая фикстура нагрузочного сценария claim:
  mock-каталог не содержал обязательного `ROBOT_UNSORTED`. Фактические состояния:
  50 успешных ensure_tag, 50 temporary_component_unavailable и 50 prerequisite_failed.
  Обновлены только каталог и ожидаемый компонент теста; повторный exact test
  на 200 сессий прошёл за 3,97 с. Порог задержки и проверки доставки не ослаблены.
  Полный 14-минутный прогон после изменения одной фикстуры не повторялся.
- Focused API worker/actions/lifespan: 33 passed. Recovery и завершение
  выполняющегося потока сохраняются; на unsupported хосте очередь не опрашивается.
- Web unit: 2 899 passed (`npm test -- --maxWorkers=2`); targeted lifecycle/PWA:
  201 passed; build, lint, 53 теста вспомогательных web-скриптов прошли.
- Production PWA: 48 сценариев прошли — по 16 в Chromium, Firefox и WebKit,
  включая 390/1440 px, старый установленный клиент, offline restart, очереди
  действий/медиа, все роли после обновления и production CSP.
- Первый PWA-прогон остановился для Firefox/WebKit из-за отсутствия их
  исполняемых файлов; после установки закреплённых Playwright браузеров все
  32 соответствующих теста прошли. Это исправление локальной тестовой среды.
- Host: 1 308 passed. После уточнения обработки socket timeout отдельно
  повторены все 27 broker-тестов: passed. Четыре новых idle-сценария до фикса падали.
- Ruff API: check и format clean; registry технического долга, границы модулей,
  согласованность версий, миграций и release-contract прошли.

## Ограничения

- Восьмичасовой тест не запускался по прямому указанию владельца.
- Тесты и снимок ресурсов не доказывают отсутствие всех утечек под любой нагрузкой.
- Модель не скачивалась и не запускалась. CUDA/AGX и производительность модели
  требуют отдельной проверки после получения обученных весов.
- OTA v1 остаётся без подписи издателя по выбору владельца; SHA-256 проверяет
  целостность. Миграционная голова — 0059, в совместимость добавлена rc.33.
- Старые публикации и история Git с прежним корпусом знаний этим выпуском
  не удаляются. Новый пакет не содержит и не загружает корпус.
