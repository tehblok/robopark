# Подготовка Robopark 0.2.0 к production

Актуально на 03.10.2026: установлен `0.2.0-rc.21.dev13181400260723547202`;
OTA завершена, обычный и root-терминалы проверены через сайт и закрыты.
Текущее состояние и оставшиеся ограничения — в [live-аудите](2026-10-03-live-host-audit.md).
Ниже сохранён исторический отчёт о кандидате от 01.10; его результаты сканирования
не следует переносить на более новые образы без повторной проверки.

На момент отчёта попытка установки 0.2.0 завершилась `host_operation_failed`
(операция `02034dc6-bf16-447c-aeb3-a1ae309ef62f`), хост оставался на
`0.2.0-rc.16.dev11074319897666147461`.

После инцидента в рабочем дереве исправлены выход из сессии при отклонённом
подтверждении TOTP и потеря точных кодов ошибок OTA в результате операции и
диагностическом архиве. На момент этого отчёта изменения ещё не входили в пакет
ниже и не были установлены на хост. Подробности и границы проверки:
[разбор инцидента](2026-10-01-ota-install-incident.md).

## Исправления относительно rc.16

- Получатели уведомлений: активная ночная смена не теряется на границе
  локальной полуночи.
- Аналитика: последовательные быстрые изменения периода, группировки и
  сравнения объединяются, а не перезаписывают соседние фильтры.
- Офлайн-сессия: известное отсутствие сети не вызывает ожидание `/auth/me`.
  Возврат сети отменяет устаревшее восстановление; отзыв сессии применяется
  до ожидания очистки хранилища. Изменение прав удаляет прежние области данных.
- PWA: одновременные запросы активации больше не блокируют друг друга;
  старые вкладки без нового подтверждения release поддерживаются. Вкладка,
  открытая в момент активации, получает согласованные JS и service worker.
  Reload ждёт состояния activated; redundant worker, RELEASE и таймаут
  активации снимают блокировку, сохраняя возможность новых локальных записей.
- Исправлены владельцы запросов, cleanup интерфейса, загрузка файла при
  недоступном предпросмотре и предупреждения статического анализа.
- Удалены восемь недостижимых обёрток страниц; действующие и совместимые URL
  остаются в маршрутах.
- Обновлены зависимости API, web и бота. Зависимости бота закреплены полным
  lock-файлом с хэшами. Непроверенные major-переходы инструментов не выполнялись.
- Сборщик OTA поддерживает stable и следующие версии; опубликованные
  миграции до `0054_park_coordinates` не изменялись. Новая миграция
  `0055_media_upload_park` добавляет nullable park scope для фото.
  Сборщик читает метаданные новых миграций декларативно, не исполняя их.
- Исправлена обрезка первого таба проверки робота на ширине 320 px;
  минимальные размеры области нажатия сохранены.
- Защита входа, CSRF, лимиты nginx, квоты медиа и права контейнеров усилены;
  результаты и ограничения перечислены в `2026-10-01-security.md`.
- Ошибка чтения настроек бота больше не оставляет бесконечную загрузку;
  неизвестное состояние токена не отображается как его отсутствие.
  Выбор архива бота использует общий локализованный компонент.

## Проверка браузеров

Playwright закреплён lock-файлом и контейнером. Chromium, Firefox и WebKit
выполняют одинаковые функциональные проверки. Для Blob/File в WebKit применён
отдельный обычный профиль: приватный контекст движка не поддерживает этот
режим IndexedDB ([Playwright #42795](https://github.com/microsoft/playwright/issues/42795),
[WebKit #156347](https://bugs.webkit.org/show_bug.cgi?id=156347)). Содержимое
multipart проверяется на реальном локальном HTTP-сервере, без подмены байтов.

Для офлайна WebKit останавливается настоящий origin-сервер и проверяется
отказ некешированного запроса: protocol offline эмуляция имеет отдельную
[проблему #42775](https://github.com/microsoft/playwright/issues/42775).

Длительный тест использует один документ, проверяет его уникальный token,
реальные wall-clock секунды, память процессов браузера, дескрипторы, таймеры,
глобальные подписки, object URLs, MediaStream tracks и реальные ошибки.
Колебание метрики не отключает проверку итогового превышения порога.
Камера в этом тесте — canvas MediaStream; API БД проверяется отдельными тестами.

## Составная браузерная приёмка и остаточные ограничения

Полный старый snapshot: **5395 passed / 1376 skipped / 179 failed**.
Старый cross-browser: **643 passed / 5 failed**. Эти сырые результаты сохранены.
Все 179 + 5 обнаруженных падений сопоставлены с содержательными повторными
проверками; независимое ревью не нашло незакрытого сценария. Итоговый ledger:
`output/audit/2026-10-01/production/browser-composite-acceptance.json`.
Это составная приёмка freeze `a6184fe0`, а не один полный зелёный прогон
нынешних 6953 тестов. Пропуски не считаются успешными проверками.

Финальные повторы: маршруты — 51/51, cross-browser затронутых функций — 21/21,
контракты визуала — 6/6, карточка задачи — 2/2. Firefox Emergency прошёл три
повтора pending и три error с прежними таймаутами. Auth snapshot закрыт одним
неизменённым повтором; WebKit shared-controls/lifecycle — одним актуальным
проходом. Редкие timing flakes длительного общего запуска не исключены.

Восьмичасовой UI-тест отменён пользователем («8 часовой тест не проводи»).
Сохранены 900 секунд частичных замеров: **USER_CANCELLED, не PASS**.

## Оставшиеся действия на хосте

- Свежий TOTP и установка уже проверенного stable OTA штатным потоком.
- Live версия, head 0055, health, сохранность данных, доступность rollback.
- Одиночная проверка публичной семантики Tuna/XFF без нагрузочной атаки.

Эксплуатационная ёмкость публичного туннеля не измерялась и не заявляется.
Физические iPhone/Safari, камера и принтер не подключены к этому стенду.
Их проверка не подменяется успешным Playwright WebKit. Реестр технического
долга остаётся явным: платформенная приёмка, дублирование автономных
manifest-валидаторов и историческое представление дат legacy SQLite.
