# Проверка контракта OTA v1

API admission и автономный verifier независимо разбирали один manifest, но API
проверял только базовую структуру. Он принимал некорректные `git_sha`,
`migration_head`, пустые или нетипизированные `changes`, повторяющиеся и
нетипизированные `compatible_from`, произвольные `requirements`, несортированный
`files` и ZIP members вида `C:/payload`. Автономный verifier эти пакеты
отклонял. При этом host consumer не является третьим parser: `ota_store.py`
вызывает тот же `robopark_ota.verify_ota`.

API inspector приведён к текущему OTA v1 contract автономного verifier. Он
проверяет те же форматы, типы, пределы, уникальность и порядок, требует точные
значения runtime requirements и нормализует `changes` через `strip()`. Ошибки
malformed JSON objects возвращаются как `OtaUploadError`; пакет отклоняется до
копирования в host staging. Canonical JSON, member hashes, archive limits и
hash-only модель OTA v1 не изменены.

Единый генератор `tests/host/ota_contract_cases.py` создаёт пакеты, а таблица в
`test_ota_contract_parity.py` задаёт изменения manifest. Каждый пакет проходит
через реальные API inspector и standalone verifier, а store-level тест фиксирует
отказ до staging. Опубликованный rc.27 и локальный кандидат rc.28 дополнительно приняты обоими
валидаторами без изменения метаданных версии. Ревью дополнительно обнаружило
путь ZIP `.`: проверка API теперь отклоняет и его; отдельная регрессия сначала
упала, затем прошла. Ещё одна регрессия проверяет ZIP с неизвестным методом
сжатия: вместо необработанного `NotImplementedError` API выдаёт штатный
`ota_invalid_container`, как автономный verifier.

Проверка ограничена синтетическими архивами, локальными файлами rc.27 и rc.28
и целевыми unit/integration тестами. Установка на Linux-хосте и полный
восьмичасовой gate не выполнялись. Формат остаётся без подписи издателя согласно
принятому решению по OTA v1.

Проверки после замечаний ревью: 16 parity и 66 в общем целевом наборе
verifier/parity/acceptance/admin OTA прошли. Полный host-набор: 1 258 passed
до последней правки обработки RuntimeError; после неё повторён целевой набор.
Реестр техдолга, границы модулей и Ruff прошли. Независимое ревью текущего diff
не оставило воспроизводимых замечаний; полный API-прогон выполняется отдельно.
