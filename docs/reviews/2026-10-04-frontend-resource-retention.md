# Ограничение временных frontend-ресурсов

Дата: 2026-10-04.

## Найденные причины

`InventoryPartsView` добавлял каждую загруженную страницу каталога в
`partsById` и удалял записи только при смене парка или потере доступа. Поэтому
обычный просмотр страниц удерживал все ранее показанные карточки до размонтирования
экрана.

`TrackerWorkspace` отдельно хранил глубину пагинации в `Map` для каждого набора
фильтров. Сами страницы уже находятся в общем `resourceStore` с LRU-пределом
128 записей, но эта вспомогательная карта не имела предела и переживала вытеснение
соответствующей страницы.

## Изменение

- Каталог теперь удерживает объединение текущей страницы и карточек, явно
  выбранных для печати. Свежая карточка текущей страницы заменяет прежнюю версию
  выбранной карточки. Смена парка и отказ в доступе по-прежнему очищают данные.
- Tracker хранит глубину только активного фильтра. При смене фильтра она
  сбрасывается; при возврате глубина восстанавливается из страницы в bounded
  `resourceStore`, если та ещё доступна. Вытесненный фильтр начинает с первой
  страницы. Обновление активного расширенного списка сохраняет его текущую
  глубину.

Явно выбранный пользователем набор этикеток может быть большим: это необходимое
состояние одной операции печати, а не история просмотренных страниц.

## Проверка

Регрессии подтверждают точное множество карточек каталога и возврат к вытесненному
Tracker-фильтру без лишней загрузки второй страницы. Целевой запуск:

```text
npm test -- --run src/domains/inventory/InventoryPartsView.test.tsx src/components/tracker/TrackerRefresh.test.tsx
```
