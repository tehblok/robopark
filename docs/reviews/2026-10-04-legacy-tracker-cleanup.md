# Удаление старого интерфейса Tracker

Дата: 2026-10-04.

## Причина

Рабочий маршрут использует `WorkPage → IssueWorkbench`. Старые
`TrackerWorkspace`, `IssueFilters`, `IssueList`, `IssueDrawer` и
`TaskBoard` не имели production-imports: они ссылались друг на друга и
оставались достижимы только из двух собственных unit-тестов.

Общие компоненты действий, деталей, совместной работы и проверки робота
используются активным `IssueWorkbench` и сохранены. Тест
`TaskCard.test.tsx`, несмотря на историческое имя, проверяет именно эти общие
компоненты и также сохранён. Общие CSS-классы не удалялись.

## Покрытие

Тесты старой накопительной пагинации не переносились: активная очередь использует
страницы из URL и отдельные bounded resource keys. Базовое отображение, выбор и
дедупликация задач уже проверяются тестами `IssueWorkbench`.

В активном наборе не хватало одной проверки: refresh детали, начатый до mutation,
не должен позже заменить свежую post-mutation задачу. Этот сценарий перенесён в
`IssueWorkbench.test.tsx` как поведенческая регрессия через публичный
`resourceStore.revalidate`.

Исправление глубины фильтров `TrackerWorkspace`, подготовленное для rc.29,
касалось неиспользуемого legacy-модуля и удалено вместе с ним. Пользовательский
эффект ограничения памяти rc.29 в этой области относится к активному каталогу
запчастей: он удерживает текущую страницу и явно выбранные этикетки.

## Границы

Удаление не меняет API Tracker, общий resource store, рабочий маршрут,
`IssueActionsPanel`, `IssueDetailPanel`, `TaskCollaboration`,
`RobotCheckPanel` или стили.
