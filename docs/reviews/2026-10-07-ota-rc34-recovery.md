# Восстановление Khadas после OTA rc.34

7 октября 2026 года обновление rc.33 → rc.34 оставило сайт в режиме
технических работ. После диагностики через SSH сайт восстановлен, затем
тот же опубликованный пакет rc.34 успешно установлен. Схема БД — 0059.

## Причина

В установленном host runtime `reconcile_ai_installation()` безусловно
вызывал `chmod`/`chown` для уже существующего `/run/robopark-ai`, в том числе
на Khadas, где ИИ не поддерживается. В `robopark-commands.service` действует
`ProtectSystem=strict`; каталог не входил в `ReadWritePaths`. Даже повторная
установка тех же прав завершалась `EROFS`.

Ошибка возникала и при активации кандидата, и в конце отката. Контейнеры,
файлы релиза и база уже вернулись на rc.33, но завершающий шаг отката не
прошёл, поэтому maintenance остался включён. Ответ 200 от `/api/health/ready`
не доказывал доступность сайта: этот маршрут намеренно исключён из блокировки.

Причина воспроизведена на хосте отдельной временной службой с теми же
ограничениями: `chmod('/run/robopark-ai', 0750)` вернул `Read-only file system`.
После разрешения записи только в этот каталог полная сверка AI installation
установленным runtime прошла с результатом unsupported host, без установки ИИ.

## Восстановление

1. Сохранены исходные journal, receipt и marker в закрытом каталоге
   `/var/lib/robopark/ops/state/manual-recovery/` на хосте.
2. Под блокировками host и OTA проверено совпадение текущего релиза,
   compose, фактических image ID контейнеров и схемы PostgreSQL со снимком
   rc.33. Проверка готовности штатным runtime прошла.
3. Штатный завершающий шаг OTA зафиксировал `rolled_back` и снял maintenance.
   Повторное восстановление базы при ручном завершении отката не выполнялось.
4. Для `robopark-commands.service` и `robopark-updater.service` установлены
   постоянные drop-in `90-robopark-ai-bridge.conf` с точечным разрешением
   записи в `/run/robopark-ai`. Прочие ограничения основных процессов сохранены.
5. После проверки SHA-256 повторно запущен исходный rc.34. Операция перешла
   в `published` в 08:26:12 UTC. Пакет, release asset и tag не изменялись.

## Изменение исходного кода

Сверка AI bridge теперь проверяет тип, владельца, группу и права каталога,
не меняя метаданные уже корректного каталога. Ссылки, неверный владелец и
небезопасные права отклоняются до изменения compose. Отсутствующий каталог
создаётся через установленную tmpfiles policy с ограничением
`--prefix=/run/robopark-ai` и затем проверяется повторно.

В unit-файлы добавлен `ExecStartPre=+...systemd-tmpfiles` с тем же фиксированным
префиксом и policy. Только этот подготовительный процесс исполняется вне
ограничений файловой системы; основной процесс сохраняет sandbox.
`ReadWritePaths=-/run/robopark-ai` обязательно содержит `-`: без него systemd
на Khadas выдаёт `226/NAMESPACE` ещё до подготовительной команды, если каталог
отсутствует. С `-` реальная проба на отдельном пустом пути прошла: tmpfiles
создал каталог `0750/root:10001`, а основной процесс подтвердил readonly `/run`
и возможность менять метаданные только разрешённого каталога. Пробная служба,
policy и пустой каталог удалены. Результат сохранён на хосте в
`ops/recovery/ai-bridge-sandbox-probe.json`.

Поведение префикса `+` описано в
[документации systemd](https://github.com/systemd/systemd/blob/main/man/systemd.service.xml);
возможность запуска при отсутствующем пути дополнительно проверена на хосте.

Это исправление предназначено для следующих сборок. Опубликованный rc.34 его
не содержит. Старый OTA consumer продолжает исполнять код установленного
релиза во время обновления, поэтому новый код кандидата сам по себе не
устраняет ограничения уже запущенной службы. На восстановленном хосте эту
совместимость обеспечивают указанные drop-in. После проверки они дополнены
подготовительной командой и optional path, как в новых unit-файлах. Разрешение
записи во весь `/run` и отключение `ProtectSystem` не требуются.

## Проверки

- Реальное воспроизведение `EROFS` и успешная проверка с точечным разрешением
  записи в systemd на Khadas.
- Повторный OTA того же пакета завершён штатно: `published`, ошибка отсутствует.
- `VERSION` на хосте — `0.2.0-rc.34`; API, web, PostgreSQL и worker — healthy.
- Readiness: database/integrations — ok; maintenance — false;
  отдельная проверка heartbeat — `worker_healthy`.
- В браузере загрузились 34 открытые задачи выбранного парка и карточка
  задачи с описанием. Проверка чтением, без изменения рабочих тикетов.
- Полный host-набор: 1315 passed. После уточнения optional path и порядка
  импортов повторный профиль AI installation + systemd: 50 passed; Ruff
  и `git diff --check` прошли. Прежняя реализация воспроизвела ожидаемые
  ошибки новых тестов.

Предыдущие тесты rc.34 не воспроизводили readonly mount namespace реальной
службы. Успешная контейнерная сборка и readiness этого ограничения не выявляют.
Восьмичасовой тест не проводился. ИИ на Khadas не включался.
