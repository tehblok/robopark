# Проверка безопасности Robopark

Актуализация 03.10.2026: на хосте установлен `0.2.0-rc.21.dev13181400260723547202`.
Исторические сканы ниже относятся к указанным образам и freeze, а не автоматически
к новому релизу. Текущая проверка и исправления описаны в
[live-аудите хоста](2026-10-03-live-host-audit.md).
Это не сертификат отсутствия уязвимостей и не подтверждение защиты внешней инфраструктуры Tuna.

## Исправления кандидата

- Browser mutations проверяют Origin/Referer/Fetch Metadata. Чужой или
  некорректный origin отклоняется; native/internal клиенты без браузерных
  заголовков сохраняются. nginx передаёт Host вместе с локальным портом.
- Перебор входа ограничен отдельно по паре логин/IP и по IP, независимо от
  смены логина. Успешный вход не сбрасывает бюджет ошибок IP. Для неизвестного
  и неактивного пользователя выполняется проверка dummy Argon2; одновременно
  в процессе допускается не более четырёх проверок пароля.
- Владелец может увидеть и удалить только свои неиспользуемые OTA-загрузки,
  в том числе устаревшие. GET не раскрывает записи других владельцев;
  DELETE повторно проверяет владельца и привязку к операции под блокировкой.
  Список ограничен 512 metadata; несовместимый пакет нельзя установить.
- nginx ограничивает частоту/одновременность API и входа, размеры тел,
  время ожидания. OTA передаётся прежними фрагментами 4 MiB и помещается в
  общий предел 16 MiB; прежнее исключение на крупный цельный ZIP удалено.
- nginx доверяет адресу клиента только от loopback и точного Docker gateway,
  вычисленного при запуске. Подставленный XFF от соседнего контейнера не
  меняет адрес. **Live-проверка 03.10 выявила общий адрес 127.0.0.1 из-за дополнительных
  loopback hops Tuna; исправление `real_ip_recursive on` установлено в rc.21.
  Карточка активности владельца через публичный сайт теперь показывает внешний IP.
  Spoofed XFF проверен на реальном локальном nginx; после OTA публичная подстановка
  заголовка повторно не выполнялась.**
- Добавлены HSTS для внешнего HTTPS, `object-src 'none'` и поддержка `blob:`
  только для фото. Исполняемый inline/сторонний JavaScript CSP не разрешает.
- Загрузки фото получили квоты по пользователю, числу сессий, общему объёму
  и свободному диску. Миграция 0055 сохраняет park scope для локальной
  проверки отзыва прав. Гонки append/complete/cleanup сериализованы общей
  блокировкой; перед offline-действием повторно проверяются текущие права.
  Legacy-сессии получают park scope через доверенную проверку задачи.
  55 профильных регрессий и 15 PostgreSQL-тестов прошли; ревью закрыто.
- PostgreSQL обновлён в пределах major 17 до 17.11. Выпущенные миграции
  неизменны; nullable park_id добавлен новой миграцией.
- Образы API/бота переведены на закреплённый Python 3.12.14 / Debian 13.7;
  web — на закреплённый nginx 1.30.5 / Alpine 3.24.2. При сборке применяются
  доступные обновления системных пакетов. Установщик pip удалён из рабочих
  API/bot образов после установки зависимостей.
- API и worker запускаются без Linux capabilities, с `no-new-privileges`
  и пределами процессов 512/256. Реальный smoke подтвердил UID 10001,
  CapBnd=0, NoNewPrivs=1, запись данных и запуск pg_dump.

## Границы защиты

Адреса API видны пользователю браузера. Их скрытие не является защитой:
безопасность обеспечивают серверные проверки сессии, прав, парка и конкретного
действия. HTTPS защищает передачу до Tuna; сам провайдер завершает внешний TLS
и входит в доверенную инфраструктуру. Защита от объёмной DDoS-атаки зависит
от провайдера и доступного канала; локальные лимиты этого не заменяют.

Пароли обрабатываются Argon2, сессионные токены генерируются криптографически
и сохраняются в БД в виде SHA256-хэша. Cookie выставляется с HttpOnly и
SameSite=Lax; production installer задаёт Secure=true (локальный dev default
другой). Ключ шифрования интеграционных секретов не имеет встроенного
production-значения; отсутствие ключа запрещает запись секретов.
Это проверка кода и штатной конфигурации, а не чтение приватного env хоста.

В просмотренных обработчиках upload/restore независимое ревью не нашло
выполнения произвольных команд извне: команды передаются argv, импорт бота
проверяет ZIP/JSON, восстановление использует проверенный backup artifact.
Это вывод по проверенным путям, не универсальная гарантия от выполнения
вредоносного кода. Хост, Docker, учётная запись владельца и источник OTA
остаются значимыми границами доверия.

Совместимый legacy-путь обновления в исходном Compose ещё использует `/host-repo` mount API/worker
без Docker-флага read-only. Возможность записи дополнительно зависит от
владельца и POSIX-прав файлов хоста; сам факт RW mount не доказывает, что
UID 10001 может их менять. Установщик создаёт release-файлы с режимами
0644/0755. Live-проверка rc.20 подтвердила, что production renderer заменяет эти
mounts: всего checkout в API/worker нет, `/host-repo/deploy/host.env` смонтирован
read-only. Каталог текущего релиза — root:root 0700. UID API/worker — 10001,
CapDrop=ALL и no-new-privileges включены. Это не меняет контракт legacy-профиля.

Владелец явно выбрал **сохранить hash-only OTA v1**. Хеши проверяют целостность,
пароль и TOTP — полномочия устанавливающего; подписи издателя нет. Пакет,
подменённый вместе с манифестом до установки, этим форматом не распознаётся.
Решение и отклонённое предложение записаны в
`docs/architecture/2026-10-01-ota-authenticity-proposal.md`.
