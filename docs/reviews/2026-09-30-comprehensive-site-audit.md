# Проверка Robopark: сайт, код и обновление хоста

Дата: 30 сентября — 1 октября 2026 года. Сайт: https://robopark.ru.tuna.am.

Проверены работающий сайт под владельцем, локальный исходный код, API, PostgreSQL, браузерные сценарии, PWA и механизм обновления. Рабочая копия содержала большой набор незакоммиченных изменений до начала проверки; они сохранены. Этот отчёт описывает дополнительную проверку и исправления текущей сессии, а не приписывает ей весь diff репозитория.

## Исправленные ошибки

| Область | Воспроизведение и исправление |
| --- | --- |
| Задачи после перезагрузки | В IndexedDB оставалась старая карточка свободной задачи после сохранённого назначения. После reload интерфейс повторно предлагал взять её. Список, карточка и мои задачи обновляются при открытии; назначение блокируется до успешного уточнения состояния. Действия офлайн в уже назначенной задаче сохраняются. Проверено браузером с настоящим API и его очередью действий. |

Сбой также наблюдался на работающем сайте. Редактор теперь отображает восстановленные данные и запрашивает актуальный каталог при открытии. Проверены сохранение, reload, последующее редактирование, предпросмотр и появление ошибки на схеме робота через настоящий API. |

Чтение перенаправлено в валидированный каталог хоста; обработчик при недоступном bridge не подставляет неверную локальную версию. Штатная блокировка HTTP-запросов в режиме обслуживания сохранена. |

| Названия вкладок | Вместо постоянного «Работа» вкладка получает название текущего раздела и продукта. Проверены переходы между маршрутами. |

Создание, изменение, удаление, двойное нажатие, сбои API и офлайн-поведение дополнительно проверялись на изолированных данных.

На момент наблюдения PostgreSQL, Worker, Tracker и Tuna отображались работающими; очередь — 0, резервная копия проверена, очистка без ошибок, свободное место — около 14,3 ГБ. Telegram-бот выключен, его токен не задан. Для системных операций настроен TOTP. Статусы являются наблюдением на момент проверки, а не гарантией дальнейшей доступности.

## Тестовая инфраструктура и устаревший код

- Vitest больше не пытается запускать production Playwright-сценарии как модульные тесты.
- Скриптовые тесты используют `node:test` и включены в `scripts/verify.sh` через `npm run test:scripts`.
- Docker-проверка `scripts/verify.sh docker` передаёт безопасные существующие пути для разбора Compose, не требуя секретов установленного хоста. Регрессия проверяет существование этих путей; реальные контейнеры из такой конфигурации не запускаются.
- Устаревшие проверки UI приведены к текущим маршрутам, мобильной навигации, названиям и протоколу `/sync/batch`. Проверки единичной отправки считают пользовательские действия, а не пустые запросы сверки.
- Проверка PWA ждёт сохранения конкретной карточки задачи перед отключением сети, а не первой произвольной записи IndexedDB.
- Нагрузочная проверка API полностью изолирована от Tracker: ожидаемые операции замоканы, неожиданный внешний клиент немедленно проваливает тест. Порог производительности не ослаблен.
- Ruff отформатировал 77 Python-файлов: 39 исходников и 38 тестов. AST с учётом type comments сравнен до/после: 77 совпадений, 0 семантических изменений. Выпущенные миграции не форматировались.
- В настройках Ruff только форматирование исключает `alembic/versions/*.py`, поскольку выпущенные миграции проверяются побайтово. Проверка правил Ruff продолжает охватывать миграции.
- Удалён старый `test_manual_restore.py`, использовавший удалённые SQLite/release_pack API. Актуальные сценарии восстановления PostgreSQL, отката, прерываний, проверок архивов и retention покрыты текущими host-тестами. Полезные проверки загрузки без сборки и сохранности журналов перенесены в действующие тесты.
- Тесты версии используют канонический `VERSION`; старые проверки подписанного release_pack заменены проверками текущего формата обновления.
- Исправлен Linux-запуск Playwright на Docker/Colima: подготовленная копия передаётся в отдельный контейнер, поэтому доступность системного `TMPDIR` через bind mount больше не требуется. Команды внутри контейнера останавливаются при ошибке. Эталонные скриншоты оболочки сверены с текущим дизайном.
- Завершение временного API-процесса по запросу теста больше не считается аварией; непредвиденное завершение по-прежнему отклоняет незавершённые запросы.
- В lifecycle E2E ожидание очереди допускает штатный повтор отправки. Завершение страницы и API упорядочено, а поздние загрузки вложений блокируются только после начала teardown. Проверки конечных состояний и выполнения действий ровно один раз сохранены. Финальный набор из 35 сценариев прошёл с тремя workers; после узкой правки teardown повторно прошёл desktop lifecycle.
