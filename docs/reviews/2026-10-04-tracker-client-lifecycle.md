# Жизненный цикл клиентов Tracker

Кэш `_CLIENTS` раньше сохранял клиент SDK под каждым использованным OAuth-токеном
без ограничения. Административная ротация очищает только обслуживший её процесс.
Другие API workers при получении нового токена добавляли клиента, сохраняя старые
credentials, SDK objects и HTTP connection pools. Параллельные первые обращения
также могли создать несколько клиентов для одного токена.

Robopark использует один платформенный токен. Теперь процесс удерживает только
последний запрошенный клиент; получение и замена сериализованы lock. Завершение
действующих запросов не зависит от того, какой клиент остался в кэше. Объекты SDK
удерживают свой connection и client; `weakref.finalize` закрывает HTTP session,
когда весь старый граф объектов становится недостижим. Отдельная очистка кэша
тоже освобождает его владение, не закрывая соединение под текущим запросом.

Проверен фактически установленный `yandex-tracker-client`: connection ссылается
на client, SDK resources — на connection; session не ссылается обратно на client.
Финализатор удерживает только метод session.close. Смена токена не прерывает уже
начатые действия и не обещает мгновенного удаления всех копий секрета из памяти:
старые SDK resources живут до освобождения, циклы объектов удаляет сборщик мусора.

Четыре регрессии сначала упали: 100 ротаций без локального admin reset;
освобождение клиента с живой SDK collection; явная очистка при действующем клиенте;
восемь одновременных первых запросов. После правки эти тесты и связанные сценарии
совместной работы прошли: 25 passed. SDK настоящий, сетевых запросов в lifecycle
тестах нет. Проверка несколько процессов не выполнялась: сценарий моделирует
worker, в котором административный сброс не вызывался.

Независимое ревью проверило граф объектов и все пути освобождения: новых
воспроизводимых замечаний нет. Полный API-набор выполняется перед интеграцией. Изменение
ещё не установлено на работающий хост.
