# Проверка подготовки AGX Orin: rc.23

Дата: 03.10.2026. Основа изменений: `960a489c4589409c7d8bc2ec8263c5963d3e2e5a`.
Проверка выполнена локально на macOS и в одноразовых Docker-контейнерах.
Это проверка кандидата, не приёмка физического GEACX1 или установленного сайта.

## Область изменений

- Ограниченное чтение Linux procfs/sysfs, публикация через существующий
  watchdog, валидация свежести и разрешённых полей в API, карточки в «Системе».
- Два ограниченных браузерных кэша ETag: TTL, число записей, размер данных,
  очистка при смене авторизации и порядок завершения перекрывающихся запросов.
- Готовые gzip-копии статических JS/CSS/SVG и согласование формата в nginx.
- Изолированный стенд с 2/4 процессами API и настройками PostgreSQL из
  поставляемых ресурсных профилей.
- Исправление тестового перехватчика чтения ZIP для Python 3.12:
  ограниченный хвост ZIP допускается, чтение большого архива целиком запрещено.

## Короткий стенд

На окончательном коде оба прогона прошли все проверки: 40 синтетических
сессий, 40 задач, основная фаза 9 секунд, четыре стресс-раунда,
не более 10 одновременных запросов. Задержка локальной заглушки — 10 мс;
искусственные Wi-Fi задержки/потери в этих smoke-прогонах отключены.

| Процессы API | PostgreSQL shared_buffers / max_connections | Покрытие PID | Результат |
| --- | --- | --- | --- |
| 2 | 512MB / 40 | 2 одинаковых PID в startup/cadence/stress | passed |
| 4 | 2GB / 100 | 4 одинаковых PID в startup/cadence/stress | passed |

Предшествующий короткий прогон 20 сессий / один стресс-раунд был отклонён:
стресс-запросы обслужили только три из четырёх процессов. Проверка не
ослаблялась; число запросов увеличено для подтверждения покрытия.
Оба успешных прогона подтвердили контракты ответов, отсутствие утечек
между областями доступа и повторной записи локальных действий.
Контейнеры и синтетические данные очищены средствами стенда.
JSON и журналы сохранены локально в `output/verification/0.2.0-rc.23/`.

Локальный Docker CLI сначала использовал legacy builder без поддержки
`RUN --mount`. Повторный Docker gate прошёл с официальным Buildx v0.37.1,
проверенным по опубликованной SHA-256, во временном `DOCKER_CONFIG`.
Глобальная конфигурация Docker и Dockerfile не изменялись ради проверки.

## Независимое ревью

Найдены и исправлены два случая с регрессионными тестами:

1. Поздний старый 200 с ETag либо без ETag мог заменить/удалить новый
   валидатор и вернуть старое тело. Порядок успешных запросов теперь хранится
   на время перекрытия; очистка выполняется в `finally`. Есть отдельные
   проверки обоих семейств кэша, позднего 304 и смены авторизации.
2. Объединение PID по всем фазам позволяло засчитать процесс, работавший
   только в начале теста. Теперь startup/cadence/stress должны содержать
   одинаковые реальные PID. Потеря, замена и отсутствие процесса отклоняются.

Повторное read-only ревью этих исправлений не выявило новых воспроизводимых
проблем. GPU load читается только для точного `nvidia,tegra234` из
документированного Orin path; generic devfreq предоставляет только частоту.
Wi-Fi RX/TX отображаются отдельно с явными неизвестными значениями.

## Ограничения

Физический GEACX1, реальный Wi-Fi/Tuna, BSP/JetPack, датчики и тепловые режимы
ещё не проверены. API в стенде запускается обычными процессами без cgroup
лимита; лимит памяти PostgreSQL применяется контейнером. Не заявляется
ёмкость 200 пользователей или оптимальность четырёх процессов для платы.

Восьмичасовой soak не проводился. Рабочий сайт и хост не изменялись.
GPU/CUDA/TensorRT, автоматический MAXN и новые настройки production-БД не
включались. Формат OTA v1, миграционная версия `0056_host_terminal` и обе
схемы NVMe сохранены. Порядок измерений: [runbook](../runbooks/geacx1-performance.md).
