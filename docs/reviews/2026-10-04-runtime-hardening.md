# Следующий срез: хранилище, дочерние процессы и сборка

Продолжение автономной доработки после опубликованного rc.26. Восьмичасового
теста нет; физическая приёмка AGX остаётся отдельной работой.

## Обработка скриптов

Обнаружено ожидание записи в stdin до начала отсчёта timeout. В Linux-проверке
с допустимым вводом 65 536 байт и pipe 8 KiB прежний код вместо timeout 0,1 с
ждал выхода дочернего процесса ~0,625 с и выпускал BrokenPipeError.

Новый цикл использует неблокирующие pipe и selector, общий deadline,
ограничение сохранённого stdout/stderr и завершение process group. Отделившийся
потомок с унаследованным stdout не удерживает локальную очистку. При ошибке
создания selector завершаются дочерний процесс и все pipe, включая ещё не
зарегистрированные. Docker-изоляция, допустимый размер ввода и лимиты ресурсов
не ослаблены. Время отдельной команды очистки Docker ограничено.

Проверки: 17 lifecycle/broker тестов; реальная Linux-регрессия с вводом
65 536 байт и pipe 8 KiB после исправления завершается за ~0,104 с. На macOS
pipe такого размера не заполнялся, поэтому для подтверждения использован Linux
в production API-образе. В настоящем Docker проверены импорты, константы,
helper-функции, UID 65534, запрет записи в образ, отсутствие сети и ошибка при
выводе 70 KiB. Это проверка sandbox, а не inference на физическом AGX.

## Очистка устаревшей политики сборки

Удалён временный список более сотни разрешённых неотслеживаемых файлов и
отдельное автоматическое включение Python-файлов legacy-бота. Список остался
от первых сборок рабочего дерева после того, как эти файлы вошли в Git.
Он позволял локальному файлу с историческим именем или новому файлу бота
попасть в пакет без явного добавления в индекс.

Теперь новые runtime-исходники необходимо сначала проверить и добавить в Git.
Незакоммиченные правки уже отслеживаемых файлов продолжают включаться в снимок;
обычный релизный OTA по-прежнему собирается из чистого Git-коммита. Проверены
старое разрешённое имя и новый Python-файл бота: до исправления попадали в
выборку; после — сборка останавливается до добавления в Git. Наборы архивов
установки и обновления прошли в общем host-наборе. Отдельно проверен `git add -N`: отметка
намерения добавить файл не считается добавлением содержимого в индекс;
действительно добавленный пустой Python-модуль допускается. Новые host helpers
без расширения также требуют добавления в индекс и больше не пропускаются молча.

## Хранение AGX

На ревью подтверждены два сценария: смена live Docker root после первоначальной
настройки managed layout и отсутствие новых systemd drop-in при OTA со старого
split layout.

Managed-операции проверяют конфигурацию Docker/containerd, systemd ExecStart и
фактический DockerRootDir запущенного демона. Независимая проверка перед запуском
служб проверяет конфигурацию без подключения к Docker, чтобы не запускать демон
через его socket и не создавать цикл зависимостей. Перенаправление data-root,
непроверяемые импорты containerd и альтернативный config отклоняются. Проверены
кавычки в TOML, сокращённые параметры с абсолютным и относительным значением.
Стандартные vendor plugin tables сохраняются; сложные top-level TOML-ключи
отклоняются консервативно. Unmanaged legacy-хосты эту политику не получают.

Целевые storage/clean-install проверки: 195 passed. Старый агент rc.26 копирует
только два независимых guard-файла и не знает будущего перечня служб. Поэтому
ранний hook уже существующей terminal-setup службы запускает код выбранного
релиза: проверяет managed layout, восстанавливает актуальные drop-in, перечитывает
systemd и записывает receipt применённой политики. Hook упорядочен после Docker.
Core после boot recovery и AI-службы перед запуском проверяют receipt;
unmanaged-хост не получает запись или daemon-reload. Ограничения основного
процесса core не ослабляются.

Регрессия использует точный замороженный `storage_setup.py` опубликованного rc.26
с проверкой SHA256 и настоящий новый renderer с добавленной службой. Отдельно
проверен rollback-инвариант: обе реализации останавливают terminal-setup, затем
запуск предыдущего core повторно применяет политику предыдущего релиза. Пять
проверок handoff/порядка/receipt проходят. Это модель Linux-хоста с подменёнными
аппаратными probes, не аппаратная приёмка GEACX1. Независимое ревью не нашло
подтверждённых P0/P1; полный старый updater под настоящим systemd ещё не прогонялся.

## Браузерный CI

GitHub run `37206237103` для rc.26 прошёл полный repository gate, аудит зависимостей
и проверку bot image, но остановился при discovery браузерных тестов: тест
помощника создавал `/work/output` вне доступного непривилегированному пользователю
каталога. Сбой воспроизведён в закреплённом Linux-образе. Скриншоты перенесены
в `testInfo.outputPath`, где они сохраняются отдельно для теста/повтора и
выгружаются существующим сборщиком артефактов. Проверка импорта также уточнена:
результат импорта может одновременно отображаться с отдельным индикатором
обновления списка документов.

Итоговая локальная проверка: 1 242 host-теста прошли за 86,10 с; отдельно
повторены пять handoff/rollback тестов после уточнения импорта в тестовом файле.
Три сценария помощника прошли в закреплённом Linux Chromium: ответ со ссылкой
на источник, импорт при 320 px и недоступность ИИ на неподдерживаемом хосте.
Они добавлены в постоянный cross-browser gate: 9 проверок на Chromium, Firefox
и WebKit прошли за 14,4 с.
Проверены ограничения a11y и отсутствие горизонтального переполнения;
скриншот мобильного импорта просмотрен. Версия, migration head, registry
технического долга, границы модулей и Ruff согласованы. Нового завершённого
полного GitHub CI для rc.27 на этом этапе ещё нет.
