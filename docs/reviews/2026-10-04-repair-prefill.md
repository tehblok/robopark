# Подсказки полей ремонта по тексту и примерам

## Поведение

Форма предлагает деталь, дефект и при наличии явной записи механика выполненное действие. Источники — уже загруженные название/описание задачи, допустимые комментарии текущего ремонта и текущее уточнение. Подстановка требует нажатия; перед заменой заполненных полей показаны старые и новые значения. Отмена сохраняет фото и текст, а ручная правка отменяет прежнюю точку возврата.

Совпадения используют текущие ID и значения каталога. Деталь с позицией должна совпасть с указанной позицией. Более длинное название подавляет общее только при перекрытии в тексте: кабель камеры не становится камерой. Несколько независимых деталей в одном предложении не дают единственного выбранного компонента. Планы, вопросы, условные формулировки, цитаты и скопированные отчёты не подтверждают выполненное действие. Варианты остаются эвристиками для проверки человеком.

Комментарий участвует только при `repair_context_eligible`, который сервер рассчитывает по активному claim и успешному start после предыдущего закрытия. Недоставленный старый цикл, замещённый отчёт, служебные сообщения и сырые Tracker-комментарии не используются. Методы ремонта из истории не подставляются даже внутри текущего цикла, поскольку после возврата оператором требуется новое подтверждение работы.

## Проверка примеров

Приватная выгрузка содержит 4175 файлов тикетов. Для проверки ключевых слов использованы заголовок и описание; комментарии и журнал изменений исключены. Разделение стабильно по SHA256 имени файла; метод-победитель выбирается по обучающей части. Проверены инварианты знаменателей, сумм альтернатив и долей. Первоначальный черновой отчёт с ошибками разделения отозван, при реализации использован исправленный результат.

Три сочетания ранжируют CHANGE выше общего списка, не выбирая его:

| Деталь и дефект | Исторические CHANGE / всего | Отложенная часть |
| --- | ---: | ---: |
| MotorControl + EL-02 | 61 / 64 | 8 / 9 |
| Переднее левое мотор-колесо + CH-03 | 51 / 51 | 10 / 10 |
| Флаг + BD-02 | 30 / 31 | 7 / 7 |

Это небольшие диагностические выборки, а не оценка точности на будущих ремонтах. Общие симптомы «не открывается», «не включается» и «нет изображения» не используются как указание на конкретную деталь. В исходниках нет текстов тикетов, авторов и частных вложений; исходная выгрузка и аудит остаются в игнорируемых каталогах.

## Верификация

- Новые проверки явного применения, отмены, сохранения фото, отрицаний, условных форм, многострочных цитат и объединённых источников наблюдались failing до соответствующих исправлений.
- Полный API-прогон: 2697 passed, 22 skipped, 1 load test deselected и 2 ошибки старых exact-response ожиданий. Обе ожидали прежний словарь без добавочного `defect_method_suggestions: {}`. После обновления только этих ожидаемых значений весь набор `test_repair_workflow.py`, `test_task_timeline.py`, `test_repair_guidance.py` прошёл: 70 passed. Рабочий код при исправлении не менялся; повторный полный API-прогон не выполнялся. 22 предупреждения относятся к зависимостям/SQLite.
- Итоговый набор web: 2805 passed, 192 файла. TypeScript/Vite build и lint прошли.
- Два браузерных сценария с локальным реальным API и синтетическим Tracker прошли: desktop и 390×844. Проверены preview, применение, отмена, фото, передача смены, возврат оператором, повторный отчёт, закрытие, отсутствие дублей, недоступный каталог и восстановление из локального кэша. Axe на форме прошёл; изображения проверены визуально. Фиксированные панели скрываются только при захвате изображения длинной формы.
- OTA builder/verifier/governance: 49 passed. Формат OTA v1, миграции и требования к проверке оператором не менялись. Проверки навигации, контраста, границ модулей, реестра технического долга и версии/миграций прошли.
- Независимое ревью выявило неполное основание объединённой подсказки. Исправлено сохранением и показом каждого исходного фрагмента; повторное ревью не нашло существенных замечаний.
- Два нестабильных web-теста уточнены: событие подтверждения отправляется после подписки; проверка ухода со сломанного маршрута не путает его error boundary с намеренно отклонёнными API-запросами другого экрана. Рабочий код этих подсистем не менялся.

## Границы поставки

Это детерминированные правила без ИИ-модели, работающие и на Khadas. Дополнительных внешних запросов подсказки не делают. Автономное закрытие задач, самообучение и развёртывание на рабочем сайте не выполнялись. Восьмичасовой тест не проводился по указанию владельца.
