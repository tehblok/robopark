- Время завершения по журналу: `2026-10-14T07:08:48.848327+00:00`.
- Пакет: `0.2.0-rc.44.dev7114536505405942334`.
- SHA-256: `b2b7b0522093ffbe2534612a3ac56a370b2a45bd05bb7ff43f9727f3ce74e31d`.

Проверено по SSH через сохранённый ключ и проверяемый ключ хоста.
Для чтения закрытого журнала использована предоставленная владельцем
учётная запись администратора. Секреты в отчёт не входят.

`/var/log/robopark/ota-update.log` содержит ошибку Docker-сборки web:
`RUN npm run build` → `tsc -b` → TS2307 для
`src/design-system/data/EntityRow.tsx` и `MetricCard.tsx`.
В исходном Git-индексе файлы есть, в доставленном OTA их нет.

Причина — `stage_release_source()` после `git checkout-index` создавал
пустой Git-репозиторий и запускал `git add --all`. Правило `data/` из
`.gitignore` заново исключало уже отслеживаемые исходники. Проверка
целостности ZIP не обнаруживает неполный, но внутренне согласованный пакет.

Сбой произошёл до snapshot/migrate/cutover. На момент SSH-проверки:

- `/opt/robopark/current/VERSION`: `0.2.0-rc.43`;
- API, web, worker, bot и PostgreSQL: running/healthy;
- `robopark.service`: active/exited, Result=success;
- локальные `/` и `/api/health/ready`: HTTP 200;
- свободно около 16 ГБ из 29 ГБ на корневом разделе.

Во время диагностики установленные файлы, данные и службы не менялись.

## Исправления

Снимок индексирует только точный NUL-separated inventory исходного Git
через `git add -f --pathspec-from-file=- --pathspec-file-nul`.
Регрессионный тест сначала воспроизвёл пропажу файла, затем подтвердил
его точные bytes внутри готового OTA и отсутствие неотслеживаемого секрета.

Отдельно обнаружена несовместимость перехода RC43 → RC44: старый
`production_config()` исключает `emergency-bridge` по списку сервисов.
Локальный вызов настоящего runtime из тега `v0.2.0-rc.43` на RC44 Compose
подтвердил отсутствие bridge при сохранённом `EMERGENCY_BRIDGE_URL` в API.
Это не причина зафиксированного TS2307, но требует исправления перехода.

Для перехода добавлен release-owned helper в ExecStartPre. Он формирует
приватный Compose overlay только для Emergency (и зависимости web при
включённой функции), проверяет реальную пару base + overlay через Docker
Compose и публикует её атомарно. Основной Compose, его current-ссылка,
образы основных сервисов, БД и host.env не меняются. Для обычного RC44
Compose overlay нейтральный, поэтому не перекрывает image следующего
обновления. При выключенной функции ошибка запуска broker не блокирует сайт.

Первый вариант, заменявший current-compose, отклонён на независимом ревью
из-за гонки с cutover. Финальный overlay не меняет эту ссылку. Штатные
OTA/rollback/repair используют существующую сериализацию lifecycle;
прямые административные перезапуски во время OTA вне этого протокола
не проверялись на реальном устройстве.

Проверки исходников 14 октября: полный `tests/host` — 1514 passed,
8 skipped; ruff и проверка diff — без ошибок. Реальный renderer из тега
`v0.2.0-rc.43` воспроизвёл потерю bridge; текущий helper и установленный
Docker Compose проверили base + overlay для включённой и выключенной
функции, повторный запуск и неизменность исходного Compose. Независимое
ревью финального варианта не выявило открытых P0/P1/P2.

Повторная установка на сервере не является частью read-only диагностики.
Успешная локальная сборка не заменяет проверку полного OTA на устройстве.
