# Проверка инструментов помощника

Реализация rc.32: нативные tool calls, каталог по роли, повторные проверки парка и полномочий, отдельные durable action receipts, подтверждение закрытия/удаления по digest и ревизии. Скрипты используют существующий sandbox и тестирование текущей ревизии. Аудит не предоставляет модели raw shell или новые сетевые коннекторы.

Исправления, найденные при проверке:

- DB recovery перенесён до проверок runtime/maintenance. Два воспроизводящих теста сначала падали, после исправления проходят.
- Закрытие повторно сверяет review внутри mutation lease: ожидание блокировки не переносит старое подтверждение на новую отправку отчёта.
- Сохранённый ответ и последующая история модели повторно проверяют доступ к данным инструментов. При отзыве роли скрываются и ответ, и квитанция.
- Повтор одинакового изменения не создаёт второй эффект. Чтение после изменения выполняется заново.
- Публикация результата сохраняет структуру JSON при удалении секретов. Квитанции не исчезают при ошибке следующего ответа модели.
- В интерфейсе принятие операции задач в outbox отличается от подтверждённого выполнения в Tracker.

Проверено на итоговой реализации до релизной упаковки:

- 168 API-тестов ИИ и диагностики; 48 lifecycle-тестов.
- Двойное подтверждение через независимые PostgreSQL-сессии: один эффект.
- 2 898 frontend unit-тестов; 24 браузерных сценария Chromium/Firefox/WebKit.
- API Ruff check и format --check, frontend lint/build, module boundaries и tech-debt registry.
- Host suite: 1 271 прошли; 19 archive-тестов сначала остановлены ожидаемой защитой unreviewed_untracked_source до git add новых исходников. После добавления весь затронутый набор архивов прошёл: 54 теста.
- Независимое read-only ревью: найденный дефект восстановления исправлен; открытых воспроизводимых замечаний нет.

История пользователя хранится до удаления/очистки. Квитанции удалённых разговоров очищаются через 30 дней. Эта квитанция нужна для защиты от повторов и проверки доступа к историческим ответам.

Полный API/CI результат и данные OTA фиксируются после завершения сборки. Реальный круг Bonsai/CUDA с инструментами на AGX остаётся аппаратной приёмкой. Рабочий Khadas не обновлялся, 8-часовой тест не выполнялся.
