# Обслуживание через экран «Система»

Раздел доступен владельцу (`royal`). Хост публикует поддерживаемые действия и
доступные объекты; веб-приложение не передаёт произвольные команды, службы,
пакеты или пути. Для запуска используется повторное подтверждение паролем и
TOTP либо recovery-кодом. Пароль и одноразовый код не сохраняются в истории.

## Результаты и скачивание

В «Истории операций» доступны последние 20 запросов этого владельца.
Завершённый результат сохраняется при повторном опросе и перезагрузке страницы.
Квитанции хранятся не менее семи дней; незавершённые запросы не удаляются по TTL.

После успешной сборки диагностики появляется **«Скачать диагностику»**.
Скачивание относится к конкретному ID, поэтому запуск следующего действия не
подменяет архив. Архив содержит ограниченную диагностику и служебные состояния;
секреты и необработанные тексты журналов не экспортируются.

В старой версии типизированная команда диагностики только выполняла doctor,
не создавая ZIP. Для такого старого результата требуется собрать диагностику
заново после обновления. Если файл уже удалён разрешённой очисткой, его
скачивание возвращает `artifact_missing`, а не другой архив.

## Перед очисткой

Сначала откройте предпросмотр. Он показывает точные файлы, метки образов или
запись собственного BuildKit, а также объём. Сам предпросмотр ничего не удаляет.
Подтверждение действует только для этого плана. Через десять минут, после
изменения объектов или исполнения плана нужен новый предпросмотр.

Тома Docker, PostgreSQL и чужие образы не удаляются. Общие слои Docker означают,
что размер кандидатов может отличаться от фактически освобождённого места.

## Контекст действий

| Действие | Что выбирает владелец |
| --- | --- |
| Проверка или обновление пакета | Пакет из закрытого списка хоста |
| Перезапуск | Поддерживаемую службу хоста |
| Откат | Подтверждённый предыдущий релиз; произвольная версия не принимается |
| USB | Устройство из обнаруженного списка, идентифицированное UUID |
| Копия или восстановление | Выбранный USB и конкретную копию из его списка |

После чистой установки откат недоступен, пока предыдущий релиз не появился.
Без безопасного USB резервные действия требуют выбора подходящего носителя.
Это ограничения контекста, а не признак неисправности остальных операций.

Не отключайте питание во время обслуживания. При потере страницы система
проверяет тот же ID; повтор с новым ID не заменяет выяснение результата уже
принятого запроса. Прерванные разрушительные действия не повторяются вслепую.

## Ключ резервного копирования

При установке и переключении OTA привилегированный установщик создаёт ключ
резервного копирования, если его ещё нет. Doctor/watchdog ключ не создают и не
меняют. Он не попадает в диагностику, API, обычный снимок или вывод команд.

Зашифрованный USB-архив без этого ключа нельзя восстановить после потери хоста.
До переустановки сохраните ключ на отдельном защищённом носителе, например:

```sh
sudo robopark recovery-key export --output /media/SAFE/robopark-recovery.key
```

Укажите реальный абсолютный путь к своему защищённому носителю. Экспорт не
перезаписывает существующий файл и создаёт его с правами `0600`. После чистой
установки импортируйте сохранённый ключ:

```sh
sudo robopark recovery-key import --input /media/SAFE/robopark-recovery.key
```

Замена другого уже созданного ключа требует явного подтверждения:

```sh
sudo robopark recovery-key import --input /media/SAFE/robopark-recovery.key --confirmation 'REPLACE ROBOPARK RECOVERY KEY'
```

Прежний ключ при замене сохраняется отдельным защищённым файлом на хосте.
Не отправляйте ни один из ключей в чат и не храните единственную копию рядом с
зашифрованным архивом. Импорт принимает только обычный файл правильного размера
с правами `0600`, без симлинка и дополнительных жёстких ссылок.

Предельный размер сжатого снимка для USB-копии — 512 МиБ, распакованных файлов
— 2 ГиБ. Слишком большой снимок отклоняется до выпуска успешной квитанции;
созданная копия проверяется теми же ограничениями, что восстановление.

## Доступ к задачам и SLA

Теги парка сопоставляются без учёта регистра, включая кириллицу. Механик видит
задачи назначенного парка и может читать проверку робота из этих задач при
любом открытом статусе. Для действий, требующих владения задачей, право claim
сохраняется. Если очередь пуста, «Показать все открытые задачи» открывает другие
статусы парка; отсутствие задач в очереди не означает отсутствие задач вообще.

Очередь и обзор сохраняют подтверждённый первый переход «В очереди» в общей
базе. Недостающая история обрабатывается worker максимум по два тикета каждые
15 секунд; ошибки доступа имеют задержку повтора. Полный обход парков не
запускается каждые 15 секунд. Повторное открытие и другие пользователи используют
сохранённое начало; обратный отсчёт выполняется на устройстве в окне
09:00–21:00 каждый день по закреплённому часовому поясу первого парка.
Закрытие и повторное открытие не начинают новый пятичасовой SLA.

## Ограничение BuildKit

Система проверяет только собственный builder Robopark в отдельном Docker config.
Учтён текстовый формат размера Buildx, например `8.192kB`.
Отчёт собственного кэша допускает до 2 МиБ и 1024 записей; это отдельный предел
от небольших отчётов Docker и проверки идентичности builder.
После успешной сборки применяется предел кэша 2 ГБ с повторным измерением.
Если не подтверждены владелец
builder, его состояние или объём после очистки, предупреждение сохраняется;
чужие builder и Docker volumes не очищаются.

### Активный терминал

Перед операцией хоста завершите терминальные сессии. Ответ `terminal_active` означает занятой терминалом хост. Одновременный запрос обслуживания может закрыть сессию с `host_operation_requested`, чтобы освободить блокировку. Правила доступа, root и восстановления описаны в [runbook терминала](royal-host-terminal.md).
