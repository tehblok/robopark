# Изолированное локальное демо

Запуск из корня репозитория:

```sh
python3 scripts/isolated_demo.py
```

Для сквозной проверки с настроенными в демо Tracker и Robot API запускайте
новый экземпляр с явным разрешением этих двух HTTPS-интеграций:

```sh
python3 scripts/isolated_demo.py --allow-integrations
```

Обычный запуск оставляет внешнюю сеть закрытой, даже если в интерфейсе уже
сохранён токен: API и worker получат отказ сетевого guard до проверки токена.
Флаг действует только при старте; текущий экземпляр нельзя переключить без
перезапуска. При остановке изолированного демо его временные данные удаляются,
поэтому не останавливайте экземпляр с введёнными настройками ради смены режима.
Разрешение интеграций ограничено HTTPS-адресами Tracker и Robot API; оно не
меняет настройки рабочего хоста.

Для короткой автоматической проверки запуска и немедленной остановки:

```sh
python3 scripts/isolated_demo.py --smoke
```

Нужны уже установленные зависимости API и web, Docker и локально доступный образ `postgres:17-alpine`. Скрипт не скачивает образ. Он запускает отдельный временный PostgreSQL без постоянного тома, выполняет чистые миграции, поднимает API, worker и Vite на случайных адресах `127.0.0.1`, проверяет вход всех пяти ролей и показывает адрес страницы. Пароли и ключи генерируются на каждый запуск. Путь к одноразовому файлу входа для всех пяти ролей с правами `0600` выводится только во время интерактивного запуска; содержимое не печатается. После `Ctrl+C` скрипт завершает только созданные им процессы, удаляет свой контейнер и временные данные.

API и worker запускаются из временного каталога без чтения рабочей `apps/api/.env`. Они получают только необходимые параметры и ограничены локальными сетевыми соединениями. Рабочая база, установленные контейнеры, фиксированные dev-порты и внешние интеграции не используются. Проверка `--smoke` подтверждает запуск компонентов, HTTP-вход владельца и ответ `/admin/system/summary` со свежей метрикой worker, измеренным диском и работающей PostgreSQL; отсутствие host agent в этом локальном режиме явно допускается. Она также создаёт два временных парка, открывает отдельные HTTP-сессии администратора, оператора, механика и водителя, проверяет назначенный парк для рабочих ролей и доступ к «Системе» только у администрации. Полный проход экранов и функций выполняется отдельно в браузере. Настройка реальных Tracker и Robot API требует отдельной тестовой области и не входит в изолированный smoke.
