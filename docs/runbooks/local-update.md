# Локальное обновление Robopark

Пакет предназначен для существующей установки Linux ARM64 (Khadas VIM4,
AGX Orin). Перенесите архив на хост и распакуйте в отдельный каталог.
Запустите из него:

```sh
sh UPDATE.sh
```

Сначала проверяются контрольные суммы и OTA. Для запуска обновления введите
`ОБНОВИТЬ`. Пакет не запускает чистую установку и не удаляет базу, пользователей,
парки, фотографии или настройки Tuna. Повторно вводить токены не требуется.
Список допустимых прежних версий указан в `SOURCE-SNAPSHOT.json`.

После восстановления приложения обновление запускает обратно включённую
службу `robopark-tuna.service`: systemd останавливает её вместе с основным
сервисом. Новая служба приложения также ставит запуск включённой Tuna в
очередь после своего старта: это действует и при первом веб-обновлении,
которое выполняет updater старой версии. Запуск не ожидает зависимую службу
внутри `ExecStartPost`, а финализация не перезапускает уже активный туннель.
Отключённая владельцем служба не включается. Ошибка запуска Tuna
сообщается отдельно и не откатывает исправную базу приложения.

Обновление собирает контейнеры на хосте: нужны доступ к реестрам пакетов,
питание и свободное место для кандидата, текущего релиза и резервного снимка.
Не выключайте хост во время выполнения. Выполнение включает снимок данных,
проверку кандидата, переключение и проверку работоспособности. При ошибке
сохраните сообщение и журнал `/var/log/robopark/ota-update.log`; не удаляйте
контейнеры или каталоги вручную. Автоматический возврат проверяется движком;
при ошибке возврата потребуется диагностика на хосте.

После успеха откройте сайт с сетью и дождитесь обновления PWA. До этого старый
клиент может показывать прежний интерфейс. Проверьте очередь/SLA, график,
проверку робота и экран «Система»; затем перезапуск PWA без сети и возврат связи.
Первый вход требует сети. Подтверждённый аккаунт доступен офлайн до 72 часов
после последней серверной проверки; явный выход запрещает восстановление.

В пакете: выбор акцента, циклические смены и отсутствие без сдвига цикла,
обратный SLA, сохранение данных при переходах, восстановление офлайн-сессии,
компактный индикатор связи, удаление карты парков и кнопки «Свернуть».
Также исправлены доступ механика к задачам и проверке, общий кэш начала SLA,
контекст управляемых host actions, история результатов и скачивание диагностики.
Подробности и сохранение ключа USB-копий — в `SYSTEM-OPERATIONS-RU.md`.

Для обновления через сайт распакуйте архив и выберите файл `.ota`, а не
`.tar.gz`, в разделе обслуживания системы. Манифест нового пакета хранится
без сжатия, чтобы его мог прочитать установленный клиент перед загрузкой.
Остальное содержимое сжато; сервер по-прежнему проверяет весь пакет.

Это локальный проверенный снимок рабочего дерева, а не подтверждение полной
приёмки на ARM-хосте. Недоступные серверные действия остаются защищёнными.
SHA-256 подтверждает целостность, но не подлинность отправителя; передавайте
пакет доверенным локальным каналом.

### Переход со старого runtime к терминалу royal

Для `rc.16.dev11074319897666147461` сначала требуется проверенный foundation `rc.17.dev16437318597787721811`; только затем пакет терминала. Прямую установку feature на rc.16 запрещает список совместимости. Пакеты прежних неудачных попыток не переиспользовать. Подробнее: [терминал royal](royal-host-terminal.md).
