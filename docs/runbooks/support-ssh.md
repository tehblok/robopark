# Резервный SSH через Tuna

Опциональный доступ для обслуживания Khadas и AGX Orin. Установка приложения
и OTA сами его не включают. Требуются Linux с systemd, установленный
`openssh-server`, клиент Tuna и подписка с зарезервированным TCP-портом.

Схема: ноутбук → постоянный TCP-порт Tuna → `127.0.0.1:2222` → отдельный
OpenSSH → пользователь `robopark-support`.

## Подготовка

В этом развёртывании используется один клиентский Ed25519-ключ для Khadas
и будущего AGX. Его публичная часть поставляется рядом со скриптом:
`deploy/support/robopark_support_ed25519.pub`. При установке она используется
по умолчанию; `--public-key-file` позволяет явно выбрать другой ключ.
На хост передают только `.pub`; закрытый ключ остаётся на ноутбуке.

Скопируйте `deploy/support/ssh_access.py` и соседний `.pub` из проверенной
версии репозитория на хост. Например, после установки Robopark:

```sh
sudo python3 ssh_access.py install --alias ssh --location ru
```

Команда подготавливает конфигурацию. Она не запускает новый туннель.
Токен берётся из существующего закрытого `/etc/robopark/tuna.env`; через
`--tuna-env` можно указать другой файл того же формата. В отдельную конфигурацию
копируется только `TUNA_TOKEN`, без настроек HTTP-туннеля. Значение токена
не нужно передавать в аргументах команд или переписке.

После проверки подготовки включите доступ:

```sh
sudo python3 /usr/local/libexec/robopark-ssh-access.py enable
sudo python3 /usr/local/libexec/robopark-ssh-access.py status
```

Для явного включения при первичной установке есть флаг `install --enable`.
Статус systemd подтверждает запуск процессов, но не доступность внешнего
адреса: её проверяют отдельным SSH-подключением с ноутбука.

## Подключение и права

Сверьте отпечаток ключа хоста из `status` с первым SSH-подключением через
доверенный канал, например уже открытый терминал Robopark. Не отключайте
проверку ключа хоста. Используйте адрес и порт из своего кабинета Tuna:

```sh
ssh -o IdentitiesOnly=yes -i ~/.ssh/robopark_support_ed25519 -p 39613 robopark-support@ru.tuna.am
```

`39613` — порт текущего развёртывания, а не общий порт Robopark. Алиас `ssh`
резервируется в Tuna и передаётся как `--port=ssh`.

Вход разрешён только по установленному Ed25519-ключу. У `robopark-support`
нет sudo и членства в группах Docker, adm или systemd-journal. Root по SSH
запрещён. Для операций с правами root сохраняется существующий терминал
Robopark с отдельным подтверждением TOTP. Эта проверка сайта не переносится
автоматически на OpenSSH.

Учётная запись `robopark-maint` и штатная служба SSH на порту 22 не меняются.
SSH-соединения зашифрованы между ноутбуком и OpenSSH хоста; TCP-туннель
передаёт этот поток. Для подключения не используется встроенный SSH-сервер Tuna.

## Резервная копия клиентского ключа

`deploy/support/robopark_support_ed25519.age` — зашифрованный закрытый ключ.
Для расшифровки используется тот же AGE identity-файл, что и для полной
базы знаний. Архив SSH хранится отдельно: установщик знаний не читает его
и не передаёт содержимое ИИ. SSH-установщик также не расшифровывает этот файл
и не размещает закрытый клиентский ключ на сервере.

Отпечаток публичной части:
`SHA256:hw4DRwXsgYjQKWqPEyFannI6djzYBIscrqFaLfeKWnQ`.

На доверенном ноутбуке с установленным `age` восстановление выполняется так
(укажите путь к своему AGE identity-файлу; сам секрет в команду не вставляется):

```sh
umask 077
age --decrypt --identity /path/to/knowledge.agekey \
  --output ~/.ssh/robopark_support_ed25519 \
  deploy/support/robopark_support_ed25519.age
ssh-keygen -y -f ~/.ssh/robopark_support_ed25519 > ~/.ssh/robopark_support_ed25519.pub
ssh-keygen -lf ~/.ssh/robopark_support_ed25519.pub
```

Если файл уже существует, сначала проверьте его отпечаток: не заменяйте рабочий
ключ вслепую. Владение ключом расшифровки знаний теперь позволяет восстановить
и этот SSH-ключ; храните identity-файл отдельно от публичного репозитория.
Для независимого развёртывания другого владельца выбирают его собственный
публичный ключ через `--public-key-file`.

## Службы, обновления и отключение

Две отдельные службы:

- `robopark-support-sshd.service` — локальный SSH-сервер;
- `robopark-support-tuna.service` — постоянный TCP-туннель.

Они не зависят от работоспособности сайта, API или Docker. Перезапуск
туннеля после сбоя сети восстанавливает возможность новых подключений;
оборвавшаяся SSH-сессия сама не продолжает выполненную команду.

Конфигурация хранится в `/etc/robopark-ssh`, домашний каталог — в
`/var/lib/robopark-ssh/home`, управляющий скрипт — в `/usr/local/libexec`.
Эти пути находятся вне каталогов релизов Robopark и не заменяются OTA или
откатом приложения. Обновление скрипта выполняют отдельно проверенной версией. Перед заменой
публичного ключа, токена, алиаса, региона или конфигурации отключите доступ
командой `disable`, повторите `install`, затем `enable`. Операцию выполняют
через встроенный root-терминал или физический доступ: отключение завершает
SSH-сессии этого сервиса. Установщик откажет менять активную конфигурацию.
Идентичный повторный запуск установки сохраняет работающие службы.

Отключение закрывает туннель и останавливает только эти две службы:

```sh
sudo python3 /usr/local/libexec/robopark-ssh-access.py disable
```

Оно сохраняет ключи и конфигурацию для повторного включения. Удаление
приложения Robopark также не удаляет этот независимый способ восстановления:
если хост выводится из эксплуатации, отключите доступ отдельно и отзовите
или перенесите туннель в Tuna.

## Переезд Khadas → AGX

1. Установите Robopark, OpenSSH и Tuna на AGX, затем подготовьте SSH тем же
   публичным ключом, пока без `--enable`.
2. Сохраните отпечаток нового SSH-сервера AGX. Закрытые ключи хоста Khadas
   переносить на AGX не нужно.
3. Отключите отдельный SSH-туннель Khadas, затем включите его на AGX с теми
   же алиасом `ssh` и регионом `ru`.
4. Сверьте новый отпечаток через доверенный канал и обновите запись
   `[ru.tuna.am]:39613` в `known_hosts`. Не удаляйте её вслепую при предупреждении.
5. Проверьте вход, передачу файла и восстановление туннеля после перезапуска.

Один зарезервированный адрес используется одним активным туннелем.
Для одновременного доступа к обеим платам нужны два разных зарезервированных
порта. После переключения адрес для клиента остаётся прежним.

Документация: [порты Tuna](https://tuna.am/docs/tunnels/ports/),
[TCP-туннели](https://tuna.am/docs/tunnels/tcp/),
[параметры OpenSSH](https://man.openbsd.org/sshd_config).
