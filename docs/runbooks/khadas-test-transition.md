# Перевод бывшего production Khadas в test поверх RC43

Назначение утверждено владельцем 14 октября 2026: выключенный бывший production
Khadas становится тестовым сервером `https://roboparktest.ru.tuna.am`.
Tuna reservation ID `834066`, subdomain `roboparktest`, region `ru`.
Входящий SSH/TCP-туннель для установки и работы Mac не требуется.
AGX production не изменяется этой процедурой.

Используется отдельный однофайловый установщик `Robopark-Khadas-Test-2335.pyz`.
Он содержит ранее проверенный OTA `0.2.0-rc.44.dev7114536505405942335`,
настройки именно этого стенда и публичный подписанный профиль Mac.
Содержимое исходного OTA не меняется; это надстройка для перевода существующей
установки, а не новый вариант команды чистой установки.

## Первый запуск на самом Khadas

1. Перед включением исключите доступ Khadas к интернету: отключите Ethernet
   и Wi-Fi/точку доступа, к которой устройство подключается автоматически.
   Старые службы могут запуститься сразу после загрузки ОС. Скрипт не может
   остановить их до своего первого запуска.
2. Перенесите один файл `Robopark-Khadas-Test-2335.pyz` флешкой на Khadas.
   Сверьте SHA-256 с файлом `SHA256SUMS` из комплекта на машине загрузки.
3. В локальном терминале Khadas, из каталога с файлом, выполните:

   ```sh
   sudo python3 ./Robopark-Khadas-Test-2335.pyz
   ```

4. Скрипт проверит пакет, сохранит прежние настройки, отключит старые HTTP/SSH
   туннели, бота, фоновые службы и автозапуск прежних контейнеров. Подключайте
   интернет **только после сообщения о завершённом карантине** и запроса Enter.
5. После Enter выполняются резервное копирование БД, изоляция тестовых
   интеграций, настройка нового домена и обычное OTA-обновление. Docker
   скачивает зависимости и собирает образы: интернет нужен на этом этапе.
   Не закрывайте терминал и не отключайте питание.
6. Завершение подтверждается проверкой версии, локального API, фонового
   обработчика и тестового HTTPS origin. Войдите в `https://roboparktest.ru.tuna.am` прежней учётной
   записью Robopark. После перехода потребуется новый вход.

Для проверки файла без установки, включая macOS:

```sh
python3 ./Robopark-Khadas-Test-2335.pyz --verify
```

Требуется Python 3 с `cryptography`; на установленном RC43 библиотека используется
OTA-механизмом. На произвольной машине эта зависимость может отсутствовать.

## Что сохраняется и что изолируется

Сохраняются БД, пользователи, парки, карточки, сообщения, история, вложения,
пароли аккаунтов и ключ шифрования существующих данных. Чистая установка,
форматирование и удаление Docker volumes не выполняются.

Перед изменениями в `/var/lib/robopark-test-transition` создаются закрытые
копии прежних env/Compose и полный PostgreSQL dump. `pg_restore` проверяет
данные архива до SQL-изменений. Исходная копия при повторном запуске не
перезаписывается. Эти файлы содержат секреты — их нельзя публиковать или
пересылать вместе с диагностикой.

На тестовой копии отключаются прежние токены Tracker, Emergency и Telegram,
сбрасываются push-подписки и активные веб-сессии. Незавершённые внешние действия
переводятся в `needs_attention`; старые уведомления завершаются как `expired`.
История выполненных действий остаётся. Это предотвращает отправку старой
production-очереди после подключения отдельной тестовой интеграции.
Старые Telegram-расписания и AI-автоматизации отключаются, ожидающие отправки
и AI-действия завершаются без выполнения. Сохранённые команды управления
хостом убираются из активной очереди с сохранением закрытой копии; их состояния
в панели и БД переводятся в завершённую ошибку `request_superseded`, чтобы
старые операции не перезапускались и не блокировали новые.

У test отдельный UUID, cookie name и CORS origin. Emergency работает через
Mac-пул; прямой серверный fallback выключен. Публичный подписанный deployment
profile размещается автоматически. Для Mac используйте соответствующий
`Robopark-0.2.0-rc.44.dev7114536505405942335-arm64.pkg`, новый origin и свой
аккаунт; корпоративный SSO остаётся отдельным входом.

Боевой бот, прежний публичный SSH-туннель и автоматическое серверное обновление
остаются отключёнными. Не включайте их копированием production-настроек.
Тестовый Telegram и другие внешние записи настраиваются отдельно. Работа
локального API, интерфейса, офлайн-синхронизации и Emergency-пула проверяется
без действующих боевых токенов.
После проверок возвращаются штатные службы диагностики, watchdog, резервного
копирования и обработки новых команд панели. Серверный updater работает в
ручном режиме; это не отключает предложение обновлений в Mac-клиенте.

## Если выполнение прервалось

Оставьте исходный `.pyz` и каталог состояния. Запускайте тот же файл повторно;
он использует прежний UUID и резервную копию. Прерванную OTA-операцию именно
этого пакета скрипт сначала передаёт штатному механизму восстановления и
проверяет результат, затем повторяет обновление. Чужая незавершённая операция
или ошибка отката останавливает выполнение для диагностики. Завершённая
ошибка staging прежнего …2334 не препятствует новому обновлению.
Не удаляйте карантинные systemd drop-in файлы и не восстанавливайте прежние
`host.env`/`tuna.env` вручную — это может вновь поднять production-туннели.

Ошибка не запускает автоматический возврат к боевому домену. Откат OTA-версии
и возвращение серверу production-роли — разные операции; эта процедура
разрешает только перевод Khadas в test.

## Разработчикам комплекта

- `scripts/khadas_test_setup.py` — проверка, карантин и управляемый переход.
- `scripts/khadas_test_isolation.py` — проверенный backup и транзакционная
  изоляция старых внешних интеграций.
- `scripts/build_khadas_test_setup.py` — сборщик zipapp по белому списку файлов.
- `tests/host/test_khadas_test_setup.py`, `test_khadas_test_isolation.py`,
  `test_build_khadas_test_setup.py` — регрессии; дополнительно проверяется
  реальный PostgreSQL и готовый zipapp.

Проверка SQL проведена на PostgreSQL 17.11 со всей схемой миграций RC43
`0062_notification_retention_idx`; отдельная проверка подтверждает сохранение
данных, настоящий restore исходного dump и повторный запуск без его перезаписи.

Подпись профиля делается на машине владельца релиза через
`scripts/sign_macos_deployment.py`; закрытый ключ в комплект не входит.
Подтверждение аппаратной установки фиксируется отдельно после запуска на Khadas.
