# Тестовый релиз Robopark: Khadas VIM4, AGX Orin и macOS agent

Для перехода RC9→RC10 используйте [заметки RC10](../releases/0.2.3-rc.10.md)
и [схему сохранения сессии Mac](../architecture/2026-10-16-mac-session-continuity.md).
Сборочные проверки и фактическая приёмка публикуются раздельно: `verification.json`
и `live-verification.json`. Наличие пакета не означает успешной живой проверки SSO.

Этот релиз готовит один серверный `.ota` для ARM64 Khadas VIM4 и NVIDIA AGX
Orin. Любое из устройств можно назначить тестовым или production-сервером во
время чистой установки. Профиль ресурсов выбирается по фактическим RAM и CPU:
`vim4-safe` либо `orin`. Наличие CUDA/ускорителя остаётся дополнительной
возможностью AGX и не требуется для общих функций сайта, БД и Emergency bridge.

Физическая установка на устройства и проверка производительности этим выпуском
ещё не выполнены. Строгая подготовка GEACX1/AGX остаётся отдельной процедурой и
не применяется к Khadas автоматически.

## Сборка комплекта

Сначала проверьте изменения и создайте локальный commit файлов релиза. Скрипт
не выполняет `git add`/`commit` и откажется собирать при незакоммиченных изменениях
или untracked исходниках. Внутренний manifest OTA содержит commit реального
исходного кода; внешний manifest также сохраняет Git tree:

Для Mac сборка проверяет неизменяемый подписанный Keychain broker в
`deploy/macos-keychain-broker/v1/arm64`. Он копируется без повторной сборки или
подписи. Проверить его можно командой
`apps/api/.venv/bin/python scripts/freeze_macos_keychain_broker.py`.
Отсутствие файла, несовпадение исходников или хеша останавливает сборку: замена
этого компонента требует отдельной версии и миграции существующих записей.

```bash
apps/api/.venv/bin/python scripts/build_test_release.py /absolute/path/to/output
```

Когда тестовый macOS `.pkg` готов, его можно включить в тот же комплект:

```bash
apps/api/.venv/bin/python scripts/build_test_release.py /absolute/path/to/output \
  --macos-pkg /absolute/path/to/Robopark-<VERSION>-arm64.pkg \
  --macos-update-root /absolute/path/to/update-root.json
```

Файл должен называться `Robopark-<VERSION>-arm64.pkg`. Рядом с ним обязателен
подписанный `catalog.json`; Ed25519 проверяется по явно переданному публичному
`update-root.json`. Его target в канале `rc` должен указывать относительный путь
`/api/distribution/v1/macos/Robopark-<VERSION>-arm64.pkg` и совпадать с размером
и SHA-256 пакета. Сборщик экспортирует проверенный Git index во временный
snapshot, добавляет `.pkg`, `catalog.json` и однофайловый `.command`, затем включает
файлы в API image. Корневой Git index при этом не меняется, а файлы из
`.release-secrets` в релиз не допускаются.

Комплект содержит `.ota`, необязательные `.pkg` и `.command`, `release-manifest.json`,
`SHA256SUMS` и краткую инструкцию. Все артефакты должны иметь одну версию.

## Разделение test и production

Для каждого одновременно работающего сервера обязательны отдельные:

- HTTPS origin / Tuna HTTP alias;
- `ROBOPARK_INSTANCE_ID`, создаваемый установщиком;
- база данных, каталог данных и серверные секреты.

Новых TCP-портов Tuna для Mac не требуется. Mac устанавливает исходящее WSS
соединение через обычный HTTPS origin. Порт broker `8091` существует только в
сети Docker и наружу не публикуется.

Чистая тестовая установка:

```bash
sudo python3 robopark-<version>.ota install --environment test \
  --production-origin https://production.example.com
```

Чистая production-установка:

```bash
sudo python3 robopark-<version>.ota install --environment production
```

Тестовая установка включает Emergency bridge и отключает прямой server
fallback. Production по умолчанию оставляет bridge выключенным. Production
preset нельзя использовать в тестовом режиме. Установщик блокирует совпадение
тестового origin с указанным production origin.

Обычное OTA-обновление сохраняет существующий `host.env`, роль и UUID. Оно не
переводит существующий production в test и не включает bridge автоматически.

Для перехода с RC43 используйте RC44 `dev7114536505405942335` или новее.
Предыдущий `dev7114536505405942334` терял два исходных компонента web при
упаковке и завершался `ota_stage_failed`. Исправленный выпуск также дополняет
Compose, созданный старым обновлятором, приватным сервисом Emergency из
уже собранного образа API. Ручная замена файлов RC43 не нужна.
При выключенном bridge его запуск не блокирует основной сайт.

## Перед выдачей доступа

1. Сверьте `SHA256SUMS` и `release-manifest.json`.
2. На выбранном устройстве выполните чистую установку с нужной ролью.
3. Проверьте `docker compose ps`: `db`, `api`, `web` и `emergency-bridge`
   должны быть healthy; `worker` должен быть running/healthy.
4. Проверьте `/api/health/ready` и отдельный HTTPS origin.
5. Подпишите и разместите профиль сервера по процедуре ниже.
6. Установите `.pkg` только на тестовый Mac и зарегистрируйте его в тестовом
   сервере.
7. Проверьте переключение между двумя Mac, затем сценарии 0, 1, 2, 12 и 100
   подключённых агентов на стенде.

SSH-доступ и удалённое развёртывание в этот комплект не входят. До отдельного
решения не переносите production preset, credentials, чаты или рассылки на
тестовый сервер. Наличие `.pkg` в комплекте не подтверждает Developer ID и
notarization: это проверяется отдельным отчётом macOS build. Неподписанный
тестовый пакет нельзя выдавать сотрудникам как production-установщик.


## Подтверждение сервера для Mac

Mac принимает только сервер, подтверждённый подписью владельца релиза. Сам по
себе любой HTTPS-домен не получает право выдавать задания корпоративному Mac.
После установки сервера возьмите **только** `ROBOPARK_INSTANCE_ID` из
`/etc/robopark/host.env` (не копируйте весь файл с секретами). На машине сборки:

```bash
apps/api/.venv/bin/python scripts/sign_macos_deployment.py deployment-profile.json \
  --origin https://test.example.com \
  --instance-id <UUID-ИЗ-УСТАНОВКИ> --environment test --channel rc
```

Скопируйте полученный **публичный** `deployment-profile.json` на сервер как
`/var/lib/robopark/data/macos-deployment/profile.json` (в контейнере API это
`/data/macos-deployment/profile.json`), root owner, файл 0644, папка 0755. Проверьте
фактический bind mount `/data` в установленном Compose, если меняли каталог
данных. Файл не содержит паролей. Закрытый `.release-secrets/macos-update.key`
остаётся только на машине владельца релиза; сохраните его защищённую резервную
копию, он нужен для следующих обновлений. На сервер и в Git его не переносить.

Профиль действует 90 дней. Для продления или смены канала подпишите новый профиль
и атомарно замените публичный файл на сервере. Mac проверяет его при подключении;
смена канала подхватится при следующем подключении или пробуждении. Каталог
обновлений должен содержать назначенный канал. Для `production` нужны отдельный
origin/instance и явно подписанный профиль production. После истечения профиля
корпоративные задания не выполняются до его продления.

## Установка и подключение Mac

Текущий пилот: **Apple Silicon, macOS 13+**. Один `.pkg` включает полный
рабочий веб-интерфейс, нативную службу и LaunchAgent. Python, Node, Docker
и Tuna на Mac не нужны. Интерфейс открывается в окне приложения и загружается
с `127.0.0.1:18444`; порт доступен только на этом Mac, в LAN он не публикуется.
Пакет устанавливает root-owned `/Applications/Robopark.app`; агент работает
в сеансе пользователя после входа в macOS. Локальный администратор ОС всё равно
может удалить/заменить приложение: полной защиты кода от владельца Mac нет.

1. Скачайте `Robopark-<VERSION>-arm64.command`. В Terminal введите `bash `,
   перетащите файл после пробела и нажмите Enter. Скрипт проверит встроенный
   пакет и запросит системный пароль администратора для установки. Установленный
   Mac принимает локальные повторные установки и обновления с сохранением данных.
2. Откройте Robopark и войдите своим аккаунтом сервиса. В тестовой сборке уже
   закреплён `roboparktest.ru.tuna.am`; вводить адрес не требуется.
3. Одобренный активный аккаунт автоматически закрепляет Mac за первым владельцем
   и разрешает ограниченные compute-задания. Доступ к Emergency проверяется отдельно.
4. При необходимости откройте **Robopark → Служба и подключение → Войти в Emergency**.
   Корпоративный вход проходит в отдельном WebKit-окне. Агент не читает cookie
   других браузеров, его сессия хранится в Keychain. Готовность подтверждается
   реальным разрешённым чтением; отсутствие корпоративного доступа не блокирует compute.
5. В той же панели доступны состояние связи/синхронизации, автозапуск и разрешение
   системных уведомлений. Основные задачи выполняются в полном окне Robopark.
6. Для удаления используйте меню **Удалить Robopark** или тот же установочный
   файл с `--uninstall`. Данные по умолчанию сохраняются; `--uninstall-remove-data`
   удаляет также локальные данные текущего пользователя. Глобальные настройки
   macOS не меняются. Если обновление ещё выполняется, удаление ожидает его.

Скрипт не делает пакет notarized. Скачанный файл может потребовать явного запуска
через Terminal; выключать Gatekeeper глобально не требуется.

### Подготовка офлайн

В центре синхронизации нажмите **«Подготовить офлайн»** при доступной сети.
Сохраняются до 12 доступных парков, первые 50 задач и 100 роботов каждого
парка. При большем объёме интерфейс показывает, что набор неполный. Уже
открытые карточки и поддерживаемые формы используют существующий scoped cache.
Подготовленные списки живут до 72 часов; после 12 часов видна отметка об
устаревании и исходное время обновления. Офлайн-личность также истекает через
72 часа после последней успешной проверки аккаунта.

Комментарии, поддерживаемые действия и медиа остаются в очереди на Mac;
восстановление связи запускает обычную синхронизацию с idempotency key,
проверкой актуальных прав и обработкой конфликтов. Подготовка и обновление
снимков не должны очищать эту очередь. Неоткрытые карточки, страницы вне
набора, терминал, администрирование и свежая телеметрия требуют сети.

Данные снимков, identity, очереди, медиа и черновиков в desktop-хранилищах
защищены AES-256-GCM; ключ хранится в Keychain. Метаданные очереди (идентификаторы,
статусы, размер, scope) не являются полностью скрытыми. При недоступном ключе
расшифровка запрещена, перехода на незашифрованную запись нет. Logout очищает
scope; отзыв прав применяется после следующей успешной онлайн-проверки.

### Нагрузка пула

В центре синхронизации отображаются соединения, готовые/занятые/приостановленные
Mac, очередь, выполненные задания и объёмы данных. Техническая диагностика
сети и общий граф доступны Royal; оператор и администратор не получают эти
права через интерфейс Mac. Проверяется фактическая доступность
Emergency, а не только наличие сети на ноутбуке. Выбор учитывает задержку,
занятые слоты, нагрузку CPU, питание и давность участия. На Mac не более двух
одновременных чтений; батарея/экономный режим уменьшают ёмкость, критический
нагрев приостанавливает участие.

Сервер объединяет одновременные чтения одного VIN и использует общий кэш на
три секунды с повторной проверкой прав. Общий предел реальных запросов к
Emergency по умолчанию — 8/с (burst 8), включая проверки доступности. Настройка
`EMERGENCY_BRIDGE_UPSTREAM_READS_PER_SECOND` допускает 1–64; её повышение требует
измерений на стенде. Проверки доступности дополнительно ограничены 2/с.
Рост числа Mac увеличивает резерв и распределяет работу; не увеличивает
корпоративный лимит пропорционально числу сотрудников.

Пилот **не подписан Apple и не notarized**. Начиная с RC9 приложение использует
постоянный TEST-сертификат с закреплённым публичным отпечатком. Подпись Ed25519
проверяет метаданные обновления. Это не замена Developer ID. Gatekeeper
может потребовать разрешения на этот конкретный тестовый пакет в настройках
macOS; не отключайте Gatekeeper глобально. Массовая production-раздача требует
сборки с `--sign-application`, `--sign-installer` и `--notary-profile`.

## Ежедневные обновления и автономность

При запуске, пробуждении и каждые четыре часа интерфейс проверяет подписанный
каталог `/api/distribution/v1/macos/catalog.json` и показывает состояние.
Root helper проверяет и устанавливает разрешённое обновление автоматически
каждые 15 минут. Перед установкой проверяются подписанное назначение test/rc,
поколение каталога, размер и SHA-256 пакета. Понижение версии запрещено.
Каталоги действуют 14 дней; новый выпуск должен обновлять их. При недоступном
сервере текущая версия продолжает работать. После установки приложение сообщает
о новой установленной версии и необходимости перезапуска работающего интерфейса.

Новый `.ota` привозит `.pkg`, `.command` и каталог в API image. Для отдельной
публикации допустим override `/data/macos-distribution`: размещайте полный
комплект каталога и соответствующих пакетов атомарно. Override имеет приоритет
над image; профиль сервера хранится отдельно. Для локального обновления используйте
новый однофайловый `.command`, данные и регистрация сохраняются. Автоматическое
обновление через уже установленный root helper не требует нового пароля
администратора; ручной `.command` по-прежнему использует штатный запрос macOS.

RC9 сохраняет локальную браузерную сессию между перезапусками и может продлевать
серверный вход подписью ключа устройства. После миграции `0066_device_auth` нужен
один свежий вход владельца: прежним устройствам доверие не включается автоматически.
Пароль не сохраняется. Выход, отзыв устройства, смена пароля или доступа прекращают
доверие; root-терминал продолжает требовать отдельное подтверждение.

Полный рабочий интерфейс включён в пакет. Сайт со статикой может исчезнуть,
но API и каталог обновлений должны сохранять HTTPS origin. При недоступности
API остаются подготовленные данные и очередь. Рендеринг, подготовка медиа и
офлайн-хранилище работают на Mac. Пул выполняет чтения Emergency и ограниченные
операции `image_resize_v1` / `csv_render_v1`. Фото local-first; при необходимости
прямой WebRTC использует сервер только для согласования и проверки прав.
При невозможности прямой связи обработка возвращается на исходное устройство.
CSV relay по умолчанию выключен, чтобы не увеличивать Wi-Fi трафик сервера.
Финальные записи и загрузка результата остаются серверными; фактическое снижение
трафика измеряется на стенде. Произвольный код на Mac не исполняется.

Транспорт HTTPS/WSS шифруется, но при TLS termination в Tuna содержимое доступно
на этой границе. Сквозное шифрование поверх Tuna — открытый пункт до широкой
корпоративной эксплуатации. Постоянный SSO не гарантируется: истечение или отзыв
корпоративной сессии требует нового входа.


По принятой политике каждый Mac активного одобренного аккаунта с доступом к
Emergency автоматически становится доверенным источником. Отзыв устройства,
блокировка аккаунта, роли, park/VIN scope продолжают применяться. Это доверие
участникам, а не аппаратная attestation: скомпрометированный доверенный Mac
может подменить содержимое своего ответа. Подпись соединения и проверка VIN
не доказывают подлинность корпоративной телеметрии.

WebKit разрешает только предусмотренные корпоративные и OAuth-хосты; неожиданный
SSO-host блокируется. В RC9 поддержаны дочерние окна Passport и видимые ошибки
загрузки. Фактическую цепочку SSO надо подтвердить на стенде, прежде чем расширять
список. При переходе с ad-hoc RC8 может потребоваться разрешение macOS на перенос
Keychain через RP → «Подключить защищённое хранилище…». Фоновые операции RC9
диалоги не открывают и при отказе не подменяют регистрацию пустой. Последующие
TEST-сборки обязаны сохранять сертификат; потеря ключа останавливает сборку.
Миграция и чтение одной записи двумя различными сборками проверены в изолированном
Keychain; результат на установленном приложении фиксируется отдельно.
