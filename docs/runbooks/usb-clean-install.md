# Чистая установка с USB

Архив `robopark-<версия>-install.tar.gz` содержит `INSTALL.sh`, один
проверяемый `.ota`, `SHA256SUMS` и `SOURCE-SNAPSHOT.json`. Этот пакет собран из
текущего незакоммиченного рабочего дерева для новой установки. Сверяйте его
SHA-256 с опубликованной отдельно контрольной суммой и передавайте только по
доверенному каналу. `SOURCE-SNAPSHOT.json` содержит SHA-256 исходников,
установщика, инструкции и базовый Git SHA; последний сам по себе не
идентифицирует незакоммиченные правки.
Поля `version_rewrites` перечисляют файлы, которым сборщик присвоил номер
этого снимка после вычисления хэша исходного дерева.

На Linux распакуйте архив в отдельный каталог на локальном диске и запустите:

```sh
mkdir robopark-install
tar -xzf robopark-<версия>-install.tar.gz -C robopark-install
cd robopark-install
sh INSTALL.sh
```

Архив распаковывается без вложенного каталога. `INSTALL.sh` сверяет обе
контрольные суммы и `.ota`, затем
запускает интерактивный установщик через `sudo`. При чистой установке он скрыто
запросит Tuna token, отдельно полный публичный домен (например,
`robopark.ru.tuna.am`) или короткий поддомен зоны `ru` (`robopark`), и пароль первого royal. Не вводите секреты в аргументах
команд и не сохраняйте их рядом с архивом.

Поддерживаются Ubuntu 22.04+ и актуальный Armbian на ARM64/AMD64, Python 3.10+.
Перед распаковкой `.ota` сверяет Linux, архитектуру, ОС, запущенный systemd и
объём RAM с манифестом. Для профиля VIM4 нужна плата класса 8 ГБ; проверка
учитывает память, зарезервированную прошивкой. Armbian распознаётся также по
`/etc/armbian-release` на базе Ubuntu 22.04+ или Debian 12+.
На пустом хосте без Docker пакет подключает официальный apt-репозиторий Docker
и устанавливает Engine, Compose и Buildx. Нужен доступ к
`download.docker.com` и apt-репозиториям ОС. Автоматическая подготовка
поддерживает Ubuntu 22.04/24.04/26.04 и Armbian на базе Debian 12/13. Номер
Armbian 26 сам по себе не определяет базовую ОС; смотрите `ID` и `VERSION_ID`
в `/etc/os-release`. Другие
поддерживаемые ОС требуют заранее установленного Docker. Перед распаковкой
устанавливается отсутствующий Tuna CLI из официального apt-репозитория Tuna;
загруженные ключи Docker и Tuna сверяются с закреплёнными суммами. При смене
ключа установка останавливается до выпуска проверенного пакета. Затем
проверяются локальный daemon, Compose с `build --builder` и Buildx 0.14+
с `prune --max-used-space`. Существующие Docker-данные при отсутствии CLI,
конфликтующие apt-источники и несовместимые пакеты не удаляются.

Перед распаковкой на каждом разделе требуется наибольшее из объёма
манифеста, 6 ГБ и 15% ёмкости раздела. Проверяются корень, релизы и данные
Robopark, каталог Docker из локального `docker info` и `/var/lib/containerd`
(если он существует). Это проверка доступного места, а не прогноз точного
объёма сборки. Если `containerd` хранит
данные в другом настроенном каталоге, его раздел пока не определяется
автоматически: проверьте его отдельно до установки.

При работе непосредственно с `.ota` без архива скопируйте его с USB на
локальный диск и выполните:

```sh
python3 robopark-<версия>.ota verify --json
sudo python3 robopark-<версия>.ota
```

Меню появляется до проверки Docker и сети. «Чистая установка» допускается
только на хосте без файлов, служб и Docker-ресурсов Robopark. Если обнаружена
существующая установка или даже отдельный том базы данных, установка
завершится без изменения постоянных данных и до запроса токена Tuna и пароля.
Проверка платформы и свободного
места тоже выполняется до запроса этих секретов. Для новой базовой системы подготовьте пустой
хост. Автоматический перенос данных старой версии здесь не предусмотрен.

Если установка прервётся после распаковки или запуска базы, файлы и тома
Robopark сохраняются для диагностики. Повторная «Чистая установка» откажет,
пока их состояние не будет разобрано. Для новой попытки используйте отдельный
пункт «Полное удаление» с предпросмотром точных путей и объёмов, затем
запустите установку заново.

Пункт «Полное удаление» — отдельная необратимая операция. Он сначала
показывает существующие пути и точные Docker-объекты Robopark с измеренным
объёмом. Удаление начнётся только после ввода фразы
`УДАЛИТЬ ВСЕ ДАННЫЕ`. Перед её вводом отдельно сохраните нужные данные и
проверьте каждый путь и том PostgreSQL в списке. Сумма размеров образов может
включать общие слои, поэтому это размер перечисленного, а не обещание объёма,
который освободится после удаления.
В предпросмотр входят `/var/backups/robopark`, службы бота и старые
`robopark-update-check` units, если они есть. Общий BuildKit cache Docker не
считается собственностью Robopark по одному только имени проекта и не удаляется
этим пунктом; его нужно отдельно измерять и подтверждать происхождение.

Пароль первого royal вводится скрыто дважды. Не передавайте его в командной
строке. Для диагностики без установки выберите пункт 3 или выполните:

```sh
python3 robopark-<версия>.ota diagnose --output /absolute/output/directory
```

После установки включается ежедневный таймер `robopark-backup.timer` на 04:15
по времени хоста с задержкой до 10 минут. Он сохраняет проверенный снимок в
`/var/backups/robopark` с правами владельца root, хранит до 14 собственных
копий с мягким пределом 4 ГиБ (две последние подтверждённые копии сохраняются)
и подтверждает их в API только после записи на диск. Это локальная
копия на том же хосте и она не содержит закрытые файлы конфигурации из
`/etc/robopark`. Для восстановления после отказа диска отдельно нужны
защищённая копия конфигурации и проверенный сценарий восстановления. Страница
«Система» показывает отсутствие подтверждённой копии до первого успешного
запуска таймера. В разбивке диска эти снимки показаны отдельно от зашифрованных
копий для USB; ручной предпросмотр очистки не включает ежедневные снимки.
Если подтверждение API не удалось после надёжной записи копии, таймер сообщает
об ошибке. Следующий запуск сначала повторно проверяет эту локальную копию и
подтверждает прежний артефакт; при повторном отказе новую копию не создаёт.

## Telegram-бот после установки

Бот устанавливается отдельным отключённым сервисом. Владелец открывает
«Система → Telegram-бот», вводит токен существующего Telegram-бота в форме
сайта и при необходимости загружает ZIP экспорта через «Проверить архив».
Импорт показывает состав и размеры перед записью, принимает только ожидаемые
файлы и не перезаписывает существующие данные. Старые роли и Telegram ID
сохраняются, но связать их с учётными записями Robopark нужно вручную.
Экспорт не содержит offset получения Telegram updates, историю отправок и
СК-кампании, поэтому их восстановление из ZIP не гарантируется.

До включения сервиса остановите прежний отдельно установленный экземпляр
этого же бота и его таймеры. Два процесса с одним Telegram token не должны
одновременно получать updates и рассылать сообщения. Выключение в Robopark
сохраняет токен и каталог данных. Владелец видит фактический статус процесса
по heartbeat; «Работает» означает работающий процесс, но доставку сообщений
нужно проверить отдельно в тестовом чате.

Tracker token бот не получает: поиск проходит через API Robopark. Кроме
очередей активных парков владелец может добавить точные имена разрешённых
очередей в «Настройки бота». Там же сайт и Telegram-админка меняют общие
локации, роли, пользователей, профиль и паузы, расписание и кампании. Токены
вводятся только на сайте, не в Telegram. Для изменения структурных JSON-файлов
на сайте сначала выключите бота; профиль и паузы переключаются во время работы.
