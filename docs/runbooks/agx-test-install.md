# Установка Robopark 0.2.0 на GEACX1 AGX Orin

Этот архив предназначен для чистого хоста GEACX1 с образом из recovery-набора
`7611b523e3311ba08d821449236736590ec23e35`. Установщик сверяет модуль
P3701-0004, плату 510JX0 r3, Ubuntu 24.04, L4T 39.2.0, ядро
6.8.12-1021-tegra, охлаждение и NVMe. Он не перепрошивает Jetson, не меняет
DTB/BSP и не скачивает модель.

Резервную копию `khadas-20261014T071500Z` держите отдельно от установочного
архива. Файлы резервной копии и ключ восстановления в релиз не включаются.
Порядок восстановления описан в `RESTORE-KHADAS-RU.md` внутри архива.

## Подтверждённый оператором AGX

На проверенном AGX с L4T 39.2.1 recovery identity может отличаться от
reference 39.2.0. Для такого хоста используйте явный флаг:

```sh
./INSTALL-AGX.sh --operator-confirmed-platform check
./INSTALL-AGX.sh --operator-confirmed-platform install
```

Для продолжения только настройки accelerator замените `install` на `setup`.
Отчёт сохраняет наблюдаемую платформу; флаг не подтверждает работу модели.
При наличии проверенного NVIDIA postinst r39.2.1 скрипт на время установки
включает официальный пропуск boot firmware и завершает pending-конфигурацию
двух NVIDIA-пакетов. Загрузчик не обновляется; собственный marker удаляется
при выходе. Для неизвестного postinst автоматического обхода нет.

Публичный архив не содержит резервной копии и персональных секретов.
Восстановление закрытым one-click комплектом выполняется отдельно;
исходный Khadas при переносе остаётся выключенным.

## Установка

1. Распакуйте архив в отдельный каталог на AGX и перейдите в него.
2. Запустите проверку без изменений:

   ```sh
   ./INSTALL-AGX.sh check
   ```

3. Подготовьте managed NVMe по включённой инструкции
   `GEACX1-STORAGE-RU.md`. Начните с диагностики:

   ```sh
   sudo python3 robopark-*.ota storage inspect
   ```

   Затем выберите описанный в инструкции режим, выполните `storage plan`,
   сверьте устройство и UUID, выполните `storage prepare` с выданной строкой
   подтверждения и завершите проверкой:

   ```sh
   sudo python3 robopark-*.ota storage check
   ```

   В каталоге должен находиться ровно один `robopark-*.ota`. Без состояния
   storage `ready` чистая установка остановится до записи данных.

4. После успешного `storage check` обновите только индекс уже настроенных
   vendor-репозиториев. Не выполняйте `upgrade`:

   ```sh
   sudo apt-get update
   ```

   Установка не является offline-образом: интернет нужен для Docker, образов
   контейнеров и отсутствующих зависимостей из репозиториев GEACX1.

5. На пустом хосте запустите полный поток:

   ```sh
   ./INSTALL-AGX.sh install
   ```

Команда сначала проверяет SHA-256, целостность OTA и точную платформу, затем
запускает явную команду чистой установки OTA. После её успешного завершения
AGX-настройка продолжается только если `/opt/robopark/current/VERSION` точно
совпадает с версией пакета. Поэтому отмена или выход из установки не могут
изменить прежний accelerator.

Если Robopark установился, а подготовка пакетов или запуск accelerator
остановились, исправьте указанную причину и повторите только второй этап:

```sh
./INSTALL-AGX.sh setup
```

`setup` также сверяет активную версию. Он устанавливает лишь проверенные
зависимости из уже настроенных репозиториев GEACX1, блокирует удаление пакетов
и изменение защищённых компонентов NVIDIA/ядра/systemd, устанавливает
изолированный сервис `robopark-accelerator` и запускает его. CUDA toolkit без
точно указанного оператором пакета и версии не добавляется.

## Что считается готовым

Успех скрипта означает, что текущий Robopark соответствует пакету, а базовый
accelerator-сервис активен. Это ещё не подтверждает работу конкретной модели,
TensorRT engine или DLA. После появления весов их нужно зарегистрировать,
собрать engine и отдельно выполнить smoke-тесты `gpu`, `dla0` и/или `dla1`.
Edge LLM остаётся выключенным, пока нет выбранной модели, профиля и ключа.
Сервис ещё не подключён как consumer к API или worker Robopark: штатные запросы
приложения не используют его автоматически. До отдельной интеграции доступны
CLI, регистрация моделей и ручные smoke-тесты; моделей в архиве нет.

Если скрипт завершился ненулевым кодом, не считайте ускорение готовым. Вывод
содержит контролируемую причину; повторный `setup` безопасен после её
устранения.
