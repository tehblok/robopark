# Robopark 0.2.3-rc.20 — TEST network and terminal recovery

Тестовый prerelease для `roboparktest.ru.tuna.am`, совместим с RC19.
База остаётся на `0066_device_auth`. Production и Latest stable 0.2.2 не обновляются.

Если все адреса TEST из системного DNS недоступны по TLS, Mac запрашивает
резервные адреса через Cloudflare DNS-over-HTTPS. Полученные публичные адреса
проходят ту же проверку сертификата и имени TEST. HTTPS, WSS, локальный
интерфейс и обновлятор используют общий механизм. IP-адреса не зашиты в сборку,
системный DNS ноутбука не меняется. Корпоративные запросы сохраняют свой маршрут.

Резервный DNS используется только при отказе основного пути и только для
публичного тестового домена. При заданном системном HTTP/PAC/SOCKS proxy
сохраняется штатный маршрут. macOS 13 использует обычный URLSession.
Наличие резервного пути не гарантирует работу при полном отсутствии сети
или недоступности самого туннеля. После изменения настроек proxy/PAC требуется
перезапустить приложение.

RC19 успешно установлена на тестовый сервер и автоматически на Mac;
сессия владельца сохранилась. При диагностике подтверждены успешные прямые
чтения Emergency/Inventory и корректные WSS challenge от тестового сервера,
но обнаружены периодические TLS-таймауты на адресах системного DNS.
Этот выпуск добавляет резервный путь подключения. Проверка физической
нагрузки 200+ пользователей остаётся отдельной задачей. На роботах выполняются
только чтения.

В живой проверке нового транспорта получены HTTPS health 200 за 2,6 секунды
после запуска, Emergency WSS challenge за 0,24 секунды и Compute WSS challenge
за 0,24 секунды. Это проверка транспорта; она сама по себе не доказывает
завершение заданий через Mac или нагрузочную ёмкость. Полный результат
проверки установленного приложения фиксируется отдельно.

Встроенная диагностика дополнена событиями подключения Emergency/Compute: этап,
время, числовой код ошибки и код закрытия WebSocket. Успешные heartbeat
не засоряют журнал; содержимое запросов и секреты не записываются.

В отдельные периоды недоступны по TLS и основные, и резервные адреса,
тогда как браузер продолжает работать. Причина этого различия ещё не установлена;
наличие ProxyHelper на Mac не доказывает, что причиной является именно он.
Устойчивую связь этот выпуск пока не гарантирует.

Терминал теперь повторяет неудачное начальное WSS-подключение в пределах
прежнего окна 15 секунд, используя ту же подтверждённую сессию и новый
одноразовый билет. Срок доступа, пароль/TOTP и отзыв прав не изменены.
Счётчик четырёх терминальных соединений отделён от обычных запросов API:
раньше четыре активных HTTP-запроса могли отклонить открытие терминала с429.
На настоящем локальном nginx воспроизведено429 до исправления и200 после;
пятый одновременный терминальный запрос по-прежнему отклоняется.
Это подтверждённые дефекты, но их связь с конкретным отказом терминала TEST
без серверных журналов ещё не установлена.

Уточнено владельцем: корпоративный Mac всегда использует ProxyHelper вместе
с офисной сетью или VPN. Этот обязательный корпоративный маршрут сохраняется.
Production проверялась только чтением; её службы, конфигурация и версия не менялись.
