# Robopark 0.2.3-rc.9 — Tracker recovery and persistent Mac sessions

Тестовый prerelease для `https://roboparktest.ru.tuna.am`. Production не обновляется;
GitHub Latest stable остаётся 0.2.2.

Реестр роботов запрашивает в Tracker только разрешённые сочетания очереди и тега
парка и минимальный набор полей. Закрытые задачи остаются в реестре. Проверка
корпоративного доступа Mac читает не более 50 задач на часть запроса, вместо
полного прохода по истории очереди. Если VIN в этом ограниченном ответе нет,
проверка остаётся неподтверждённой. Большая история одного парка всё ещё требует
постраничного чтения; постоянного фонового индекса в этом выпуске нет.

Здоровый сервер использует общий кэш и объединяет одинаковые запросы. При сетевой
ошибке или 5xx личный Mac выступает резервом в рамках полномочий владельца.
401/403, отсутствие объекта, лимит запросов и ошибки валидации не запускают
переключение на другую личность. Личные ответы Mac не попадают в общий кэш.

Mac сохраняет локальную браузерную сессию при перезапуске. После первого свежего
парольного входа сервер может продлевать сессию по одноразовому запросу,
подписанному ключом этого устройства. Пароль не сохраняется. Отзыв устройства,
выход, смена пароля или доступа прекращают такое доверие. Запросы записи после
ошибки не воспроизводятся автоматически. Миграция `0066_device_auth` не включает
доверие старым устройствам автоматически: потребуется один свежий вход.

Тестовые Mac-сборки используют постоянный сертификат подписи, чей публичный
отпечаток закреплён в репозитории. При потере ключа сборка останавливается.
Это обеспечивает преемственность доступа к Keychain между версиями; сертификат
не является Apple Developer ID и не заменяет notarization.

Фоновые операции Keychain больше не открывают диалоги. Для перехода со старой
ad-hoc сборки доступ к прежним записям может потребовать однократное разрешение
macOS через меню RP → «Подключить защищённое хранилище…». Записи копируются в
новое защищённое пространство после успешного чтения; старые офлайн-данные не
удаляются. Если доступ не разрешён, приложение показывает состояние подключения,
а не заменяет сохранённую регистрацию пустой.

Корпоративный вход показывает ошибки загрузки и кнопку повтора с сохранением
сессии в текущем окне. Поддерживаются дочерние окна Passport, включая начальный
`about:blank`; переходы продолжают проверяться по списку разрешённых хостов,
OAuth state и владельцу. Реальная авторизация/MFA и отзыв корпоративного доступа
остаются под контролем провайдера; бессрочный корпоративный SSO не заявляется.

Технические уведомления объединяются и ограничиваются между опросами; событие
восстановления доставляется отдельно. Старые технические события не вызывают
пачку баннеров при входе, исходный inbox сохраняется. Текущие задачи, отчёты и
призывы продолжают доставляться. Квитанции доставки сохраняются между запусками.

Терминал получает heartbeat от сервера после свежей проверки прав и отвечает
в текущем подтверждённом соединении. Срок root-сессии, проверка отзыва доступа
и обязательное подтверждение root-входа сохраняются.

Доставка: OTA для тестового Khadas, единый `.command` для Mac, `.pkg` и
подписанный каталог автоматических обновлений. Сборочные и живые проверки
фиксируются отдельно в `verification.json` и `live-verification.json`.
