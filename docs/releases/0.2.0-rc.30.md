# Robopark 0.2.0-rc.30

Следующий кандидат после rc.29: сохранность локальных данных ремонта, ограничение
загрузок и хранения медиа, удаление неиспользуемого интерфейса задач.

- Offline-очистка выполняет чтение и удаление в одной транзакции. Свежие данные,
  записанные другой вкладкой, не удаляются по устаревшему снимку.
- Комментарий о выполненной работе передаётся вместе с проверкой и фото. Между
  двумя отдельными постановками в очередь больше не может исчезнуть зависимость.
- Авторизация чанка выполняется до чтения тела; входной поток ограничен 1 МиБ.
- Незавершённые зависимости медиа имеют срок хранения 30 дней. Клиент сохраняет
  Blob и прежние идентификаторы для безопасной повторной загрузки после очистки.
- Сбой между переименованием ready-файла и commit не оставляет вечный сиротский
  файл; неоднозначный результат commit проверяется свежей сессией.
- Потребление media копирует байты под общей блокировкой, освобождая её до сетевых
  вызовов. PostgreSQL не удерживает лишнюю row lock в транзакции вызывающей стороны.
- Удалены неиспользуемые TrackerWorkspace и связанные старые экраны. Рабочий путь
  WorkPage → IssueWorkbench сохранён.
- Внутри OTA находится отдельная инструкция, которая не содержит хеш предыдущего
  кандидата или ссылки на отсутствующую локальную документацию.

Сохраняются БД 0058, unsigned OTA v1, точная совместимость с предыдущими версиями
и ИИ только на подтверждённом AGX Orin. Добавлен прямой переход с rc.29.

Проверки реализации: 2 825 API passed, 30 skipped, 1 deselected; отдельно 26
PostgreSQL passed. После объединения с исправлениями очереди rc.29 — 2 865
frontend passed и 1 281 host passed. Полный ремонтный цикл и конкурентная
offline-очистка прошли девять сценариев в трёх браузерах. Lint, production build
и независимые ревью завершены успешно. Изменение номера выпуска проверяется
отдельно; финальная приёмка нового пакета в CI ещё предстоит.

Пакет не опубликован и на рабочий хост не установлен. Восьмичасовой тест и
аппаратная приёмка AGX не выполнялись. Проверки реальной PostgreSQL использовали
временный Docker-контейнер, очищенный после прогона.
