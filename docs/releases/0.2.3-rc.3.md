# Robopark 0.2.3-rc.3 — корпоративные Mac-шлюзы и адаптивный пул

Тестовый prerelease для `https://roboparktest.ru.tuna.am`. Production и
Latest stable 0.2.2 не переключаются.

- Tracker и SDC Inventory получают типизированный шлюз через Mac владельца;
  Emergency сохраняет отдельный брокер. Адреса и операции ограничены кодом,
  корпоративные credentials остаются в Keychain. Доступы к сервисам независимы.
- Mac закрепляется за первым владельцем. Оператор обслуживает себя и механиков
  своего активного парка; admin/royal — только себя. Пул вычислений общий, пул
  корпоративных полномочий ограничен владельцем, парком и правами.
- Планировщик разделяет вычисления, корпоративное чтение и запись. Выбор
  учитывает свободные слоты, нагрузку, задержку и транспортные ошибки отдельно
  по операциям. Ошибка Inventory не выключает рабочий Tracker или обработку фото.
- Записи Tracker получают постоянного исполнителя до первой отправки и
  сохраняют квитанции. Повтор подтверждённого шага возвращает результат;
  неизвестный исход не приводит к повторной отправке на другом устройстве.
  Завершённые локальные квитанции освобождаются после подтверждения сервера.
- Система поддерживает ноль Mac: веб/PWA и отдельно настроенные серверные
  интеграции продолжают работать. Серверу также могут быть доступны не все
  ручки. Бот сохраняет свои токены; отказ личного доступа не обходится другим
  корпоративным аккаунтом.
- Фото обрабатываются локально, при необходимости — напрямую на Mac через
  WebRTC. При недоступности прямой связи доступен ограниченный серверный relay:
  сначала проверяются узел и бюджет, затем передаются данные. Выход из аккаунта
  и потеря сети отменяют старую работу и исключают смешение результатов.
- Офлайн сохраняются доступные снимки данных и очередь поддерживаемых
  действий. Встроенный интерфейс Mac, веб и PWA остаются одной системой.

Mac: Apple Silicon, macOS 13+. Один `.command` содержит установочный пакет;
повторный запуск поддерживает локальное обновление. Онлайн-обновления проверяют
подписанный test/rc-каталог. Удаление доступно через меню приложения. Сборка
тестовая, без Apple Developer ID/notarization: скрипт не гарантирует отсутствие
предупреждений macOS и не отключает Gatekeeper. При необходимости запустите
файл через `bash` в Terminal.

После входа в Robopark мастер корпоративного доступа проверяет личный Tracker
OAuth и Emergency-сессию. Это последовательная настройка разных авторизаций,
а не подтверждённый единый корпоративный SSO. Сессии сохраняются, но отзыв
доступа или MFA могут потребовать повторного входа.

Khadas: `Robopark-Khadas-Test-0.2.3-rc.3.pyz` содержит OTA и подписанный test-профиль.
Бывший production Khadas включать без интернета до сообщения о карантине.
Старые production-токены и бот не включаются автоматически. Установщик рассчитан
на Khadas VIM4 / AGX Orin aarch64; серверное OTA остаётся ручным.

Границы тестового выпуска: корпоративные ответы проходят через сервер; прямой
WebRTC реализован для обработки фото. Общая БД и выдача новых удалённых заданий
требуют сервера. DHT, VPN, мессенджер и длительная автономная репликация не входят
в этот выпуск. Физическая установка на Khadas, личный корпоративный SSO и
проверка нескольких Mac в разных корпоративных сетях требуют полевой приёмки.
Нельзя считать их подтверждёнными только по локальным тестам.
Если накопится 256 локальных шагов с неизвестным исходом, новые записи через
этот Mac остановятся до сверки; автоматическое удаление таких квитанций опасно.
Отдельного интерфейса ручной сверки в этом выпуске ещё нет.
