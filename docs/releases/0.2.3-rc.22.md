# Robopark 0.2.3-rc.22 — Persistent Mac connections

TEST prerelease for roboparktest.ru.tuna.am; compatible with RC21.
Database remains 0066_device_auth. Production and stable v0.2.2 are unchanged.

Mac Emergency and Compute channels use a dedicated persistent WebSocket
session. Previously they shared the HTTP session's 120-second resource
deadline. Through the TEST CONNECT transport, reaching that deadline could
stall sends without returning an error; heartbeat recovery then disconnected
the Mac and interrupted robot checks. A local TLS/CONNECT reproducer confirms
the failure with a scaled deadline and successful exchange with the persistent
session policy.

Ordinary HTTP requests retain their bounded deadlines. WebSocket handshake
and heartbeat watchdogs still detect unavailable connections. TLS validation,
corporate ProxyHelper, owner-bound credentials and access checks are preserved.

RC21 server protocol is compatible: its signed Mac distribution catalog can
serve RC22 without a server migration. The full Khadas OTA is also provided for
normal release alignment. No robot or corporate writes are part of validation.
Physical acceptance with 200+ simultaneous users is not established.
