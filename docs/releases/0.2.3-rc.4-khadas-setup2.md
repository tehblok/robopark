# Khadas TEST installer revision 2 for 0.2.3-rc.4

The first RC4 transition installer incorrectly required
`/etc/robopark/updater.env` on the existing RC43 host. This file is absent in
the saved inventory of the former production Khadas. The installer therefore
stopped with `existing_install_required` before quarantine or data migration.

Use **Robopark-Khadas-Test-0.2.3-rc.4-setup2.pyz** on that Khadas:

```sh
sudo python3 ./Robopark-Khadas-Test-0.2.3-rc.4-setup2.pyz
```

Keep the Khadas disconnected from the internet until the installer confirms
quarantine and prompts to reconnect. The earlier preflight failure did not
disable the former production services.

This revision allows only the updater file to be absent. The current RC43
release, Compose, `host.env` and `tuna.env` remain mandatory. Symlinks and
special files are rejected. After backup and data isolation, the installer
creates the missing file with mode `0600`, GitHub updates disabled and the
server update channel set to `manual`. Original absence is recorded in the
private backup so retries cannot replace it with newly generated TEST settings.

The embedded RC4 OTA, deployment profile, instance UUID and target identity
are byte-for-byte unchanged. The corrected wrapper can resume the `prepared`
state left by the original RC4 installer. Do **not** delete
`/var/lib/robopark-test-transition` or use the clean-install command.

The original RC4 assets remain available for provenance. The revised zipapp,
ZIP and separate checksums are additive assets in the same prerelease. This
does not upgrade or rebuild the Mac application or change the stable release.

Validation covers reproduction with the legacy filesystem layout, missing
versus unsafe configuration paths, preservation of existing backups, retries
and the transition sequence with simulated host commands. Physical installation
and migration on the user's Khadas still require confirmation after launch.
