# Robopark 0.2.3-rc.19 — TEST diagnostics and Mac session recovery

Тестовый prerelease для `roboparktest.ru.tuna.am`. Совместим с RC18,
база остаётся на `0066_device_auth`. Production и Latest stable 0.2.2 не обновляются.

На macOS 14+ соединения с TEST выбирают доступный адрес из текущего DNS
по результату проверенного TLS-соединения. HTTPS и WebSocket используют
общий транспорт, а повторные запросы переиспользуют соединения. Локальный
CONNECT-посредник доступен только процессу с временным ключом и передаёт
зашифрованные данные только тестовому домену. Проверка TLS сохраняется;
корпоративные запросы идут прежним отдельным маршрутом. Настроенный системный
HTTP/PAC/SOCKS proxy сохраняет приоритет. При отказе посредника допустим
штатный прямой TLS-маршрут, включая DNS64/NAT64. macOS 13 и запуск
при недоступном локальном посреднике используют штатный URLSession.

Временный отказ проверки Emergency больше не удаляет ранее подтверждённую
корпоративную сессию после перезапуска. Запросы возобновляются только после
повторной успешной проверки владельца; подтверждённое истечение сессии
или несовпадение владельца по-прежнему требует нового входа.

В панели настроек явно обозначено, что cookie относится к прямому доступу
с сервера. Сессия владельца Mac хранится отдельно. Наличие Tracker-токена
показывается как «сохранён», а не как подтверждение доступности сервиса.

На странице «Этот Mac» Royal-владелец получает конструктор диагностики:
доступность TEST по HTTPS/WSS и чтения Emergency, Inventory, Tracker напрямую
с Mac либо через сервер. Для корпоративных проверок доступны номера роботов
1000–3000, только чтение. Проверка выполняется в фоне, одновременно запускается
одна; показываются этапы, длительность, HTTP-статус и безопасный код ошибки.
Журнал ограничен 100 событиями в памяти, без содержимого ответов и секретов.
Отказ в доступе к диагностике не сбрасывает офлайн-кэш приложения.

По документации [Tuna](https://tuna.am/docs/tunnels/http/) HTTP-туннель
поддерживает WebSocket; отдельный TCP-порт для WSS не требуется.
Для диагностики сети предусмотрен
[`tuna diagnose`](https://tuna.am/docs/troubleshooting/).
Ограничение [100 HTTP-запросов/с на домен](https://tuna.am/docs/restrictions/)
нужно учитывать при проверке нагрузки; это не измеренная ёмкость Robopark.

Транспорт не может восстановить полностью отсутствующую внешнюю связь.
Во время подготовки выпуска наблюдались таймауты TLS к TEST. Устойчивая
сквозная работа сайт → сервер → Mac пока не подтверждена; этот выпуск
предназначен в том числе для дальнейшей диагностики.
На macOS 13 нет нового выбора DNS-адресов; после редкого отказа запуска
локального транспорта он включится при следующем запуске приложения.
При смене системного proxy/PAC во время работы требуется перезапуск приложения,
чтобы пересоздать транспорт с новой конфигурацией.
Физическая нагрузка 200+ пользователей этим выпуском не подтверждается.
Живые проверки выполняются только чтением, без команд роботам.
