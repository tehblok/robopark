# Robopark 0.2.0-rc.29

Совокупные исправления после опубликованного rc.27. Промежуточный rc.28
не публикуется отдельно; прямое обновление rc.27 → rc.29 поддерживается.

- Помощник учитывает отмену, отключение, удаление и смену прав перед публикацией
  ответа; восстановление записи не повторяет модель, скрипт или внешнее действие.
- Исправлены утечки служебных записей общего кэша и клиентов Tracker, согласованы
  ревизии ответов между процессами и проверка OTA между сайтом и установщиком.
- Исправлены смена пользователя в помощнике, повторная отправка передачи задачи,
  сохранность ввода после создания кампании и освобождение превью при ошибке SHA.
- Поиск сохраняет подготовительные условия инструкции; база из 4 706 очищенных
  записей включена без изменения. Проверки поиска работают без приватных данных.
- Обновлены проверенные визуальные эталоны, удалены 80 неиспользуемых PNG;
  адаптивные проверки распределены на четыре части CI.

Подробные регрессии исходного среза сохранены в
[отчёте промежуточного rc.28](0.2.0-rc.28.md).

- Исправлено восстановление фото для повторной отправки в WebKit. Если файл
  прочитать не удалось, номер созданного репорта и текст сохраняются, а исходный
  черновик остаётся доступен для восстановления.
- Склад удерживает только текущую страницу и выбранные для этикеток позиции.
  Аналогичное исправление в старом TrackerWorkspace касается неиспользуемого
  модуля; оно не меняет рабочий интерфейс задач. Удаление этого модуля подготовлено
  отдельно для следующего среза.
- SQLite теперь сохраняет и сравнивает расписания в согласованном московском
  wall time, корректно обрабатывая входные значения с другими часовыми поясами.
  Старые naive-строки сохраняют прежний смысл; PostgreSQL продолжает использовать
  `timestamptz` без нового преобразования.
- Итоговый кэш отчётов Tracker ограничен 128 записями и 4 МиБ учтённых ключей и
  JSON payload. Просроченные записи очищаются при чтении и записи, LRU учитывает
  чтение, а слишком большой отчёт возвращается без сохранения в кэше.
- Terminal broker при 3072 записях и отсутствии живых сессий атомарно публикует
  новый epoch/revision и затем оставляет 2048 последних завершений. Старые
  descriptor отклоняются до запуска worker. Живая сессия откладывает ротацию,
  сохраняя fail-closed предел 4096.

- Очередь повторяет отправку после временно занятой блокировки синхронизации.
  Сохранённые действия больше не зависят от нового события фокуса/сети в этом
  сценарии; пустые очереди и требующие решения конфликты не опрашиваются.

- Временные установочные и обновляющие пакеты сохраняют полные release notes
  и происхождение исходников в пределах OTA v1; удалено устаревшее фиксированное
  описание локального обновления. Полный набор хоста после исправления: 1 278 passed.

- Браузерные тесты и PNG-эталоны больше не переносятся на хост внутри OTA.
  Производственная сборка, обновление и база знаний сохраняются; тесты запускаются
  из полного Git checkout. Приёмочные отчёты по-прежнему привязаны к этим тестам.

- Устранена самоблокировка вложенных SQLite-операций при совпадении файлового
  lock bucket: начало ремонта больше не ждёт собственную внешнюю блокировку.
  Конкурирующие запросы сохраняют взаимное исключение.
- Внутри OTA находится отдельная инструкция для установленной версии без
  устаревшего хеша самого архива и ссылок на отсутствующие локальные docs.

Схема БД остаётся `0058_ai_bundle_receipts`. Формат OTA остаётся unsigned v1,
восстановление выполняется снимком. `compatible_from_versions` сохранён и
дополнен точной версией `0.2.0-rc.28`. ИИ устанавливается и работает только на
подтверждённом AGX Orin.
