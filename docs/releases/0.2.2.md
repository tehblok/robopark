## Изменения

- Устранены циклы загрузки через `paths.target` и `docker.socket`: systemd больше не должен пропускать подготовку terminal/AI из-за этих циклов.
- Wi-Fi использует бесконечный autoconnect, обязательный IPv4 и DHCP timeout 45 секунд. Энергосбережение Wi-Fi и сон хоста отключены.
- Независимый таймер проверяет исходящий IPv4 HTTPS каждую минуту. После трёх неудачных проверок переподключает выбранный профиль, повторяя попытки не чаще одного раза в 180 секунд. Выключенный Wi-Fi и подключение к другому профилю не переопределяются.
- Helper установлен в `/usr/local/libexec`; конфигурация профиля остаётся в `/etc/robopark/network-recovery.json`. Обновление и откат приложения не удаляют сетевое восстановление и постоянные исправления порядка загрузки.
- Перед каждой повторной сборкой OTA проверяется владение BuildKit-контейнером Robopark, затем он перезапускается с текущими DNS хоста. Кэш и чужие builder-контейнеры сохраняются; Docker и приложение не перезапускаются. Это исправляет DNS `REFUSED` при сохранённом адресе старого подключения.
- Tuna использует HTTP/1.1 для обращений Go-клиента к API (`GODEBUG=http2client=0`), обходя наблюдавшиеся тайм-ауты HTTP/2. После ошибки служба повторяет запуск каждые 30 секунд без блокировки по числу попыток. TLS остаётся включён.
- Journal сохраняется на диск: максимум 256 МБ, 14 дней.

## Обновление

На работающем хосте используйте `python3 robopark-0.2.2.ota update` от root.
Локальный OTA завершает установку новой политики даже при обновлении старым runtime 0.2.0.
При переходе через веб-интерфейс старой версии после успешного OTA один раз выполните от root:

```sh
python3 -I /opt/robopark/current/deploy/installer/lib/install-services.py /
systemctl daemon-reload
systemctl start robopark-resilience-setup.service
```

Следующие OTA из 0.2.1 и 0.2.2 применяют политику автоматически. При откате она остаётся на хосте.
Профиль выбирается при первой установке только если активна ровно одна Wi-Fi-сеть. Если её нет, helper ничего не меняет. Существующий конфиг сохраняется; `"enabled": false` отключает автоматическое восстановление.

Проверки включают host/OTA тесты и реальный анализ графа systemd в Linux, который воспроизводит старый цикл и принимает исправленный граф. Контрольный reboot и искусственный обрыв production-сети не входят в этот выпуск.
