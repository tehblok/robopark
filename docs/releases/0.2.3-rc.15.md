# Robopark 0.2.3-rc.15 — Current blockers and adaptive Mac read queues

Тестовый prerelease. Production и Latest stable 0.2.2 не обновляются.
OTA обновляет существующий TEST; установленный Mac получает подписанное
обновление с сохранением аккаунта и корпоративных сессий.

Реестр «Роботы в работе» получает только текущие блокеры разрешённых парков:
очередь, тег, тип, приоритет blocker и незакрытый статус применяются в запросе
Tracker до чтения страниц. Закрытая история не загружается для построения
реестра; история конкретной задачи остаётся отдельным запросом. Tracker
по-прежнему использует серверный токен; fallback на Mac выбирается отдельно
для недоступного корпоративного сервиса.

Исправлена выдача Emergency-запросов Mac с одним доступным слотом, в том числе
при работе от батареи. Брокер больше не принимает собственный резерв задачи
за занятый слот. Повторная попытка на другом разрешённом Mac сохраняется.
Ошибка проверки робота теперь отображается явно с кнопкой повторения;
недоступность Emergency не трактуется как исправность робота.

Mac проверяет доступ Inventory после получения разрешённого проверочного
робота. Одновременные проверки объединяются, отменённые ответы не изменяют
готовность. Проверка корпоративных ресурсов выполняется отдельно от heartbeat,
поэтому медленный корпоративный ответ не задерживает связь с сервером.

После замены системного обновлятора его регистрация launchd обновляется
отдельным подписанным процессом, согласованным с блокировками установки.
Обычные автоматические обновления не требуют повторного ввода пароля Mac.

Чтения Emergency и корпоративных ресурсов ожидают свободный Mac в ограниченной
очереди. Новые запросы не вытесняют старые; краткий обрыв и новое подключение
того же Mac учитываются в пределах исходного срока. Inventory объединяет
одинаковые чтения на три секунды внутри одного разрешённого круга владельцев,
с повторной проверкой прав каждого получателя. Лимиты лёгких корпоративных
чтений отделены от тяжёлой обработки файлов.

Проверка регистрации и heartbeat имеют выделенные ограниченные потоки:
поток пользовательских запросов больше не вытесняет проверку связи Mac.
Регрессия воспроизводит занятость обычного пула потоков и проверяет сохранение
того же подключения, без отключения проверок прав.
После остановки и повторного запуска серверного компонента создаётся новый
пул; поздние ответы завершённого запуска не меняют его свободные слоты.

Временная ошибка проверки владельца не стирает ранее подтверждённый вход:
срок допуска ограничен часом с последней успешной проверки и не продлевается
ошибками. Новый вход защищён от поздних ответов старой проверки даже при
совпадении значения токена или cookie. Подробная схема доступности при 0, 1
и нескольких Mac: `docs/architecture/2026-10-16-resource-availability.md`.

Локальный синтетический стенд с PostgreSQL 17 и двумя API workers прошёл
200 отдельных сессий, 2 000 запросов за 30 секунд и последующий пакет
600 запросов без неожиданных ответов, таймаутов и дублирующихся записей.
Это проверка механизмов с искусственными корпоративными ответами, а не
замер пропускной способности физического Khadas или корпоративной сети.

Проверки сборки и регрессий перечислены в verification.json. Установка OTA,
обновление физического Mac и проверка всех корпоративных сценариев на целевом
сервере — отдельная приёмка; наличие пакета само по себе её не подтверждает.
