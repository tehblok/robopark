# Robopark 0.2.3-rc.25 — TEST parallel robot checks and recovery

Тестовый кандидат для roboparktest.ru.tuna.am. Совместим с RC21–RC24.
Production и Latest stable 0.2.2 не обновляются.

У Mac отдельная долгоживущая сессия WSS: обычный HTTP-дедлайн больше не
обрывает активный WebSocket через 120 секунд. Брокер отключает транспортное
per-message deflate; ограниченное сжатие полезной нагрузки сохраняется.

Для пакетных чтений увеличен лимит одного пользователя с 16 до 64 при общем
лимите 256. Ограничения очереди, параллельной работы Mac и частоты обращений к
корпоративному источнику сохраняются. Диагностика отказа записывает категорию
и число попыток без содержимого запросов и токенов.

Временная ошибка чтения отдельного робота больше не сбрасывает ранее
подтверждённую готовность всего Mac. Истечение срока проверки, отказ
авторизации и неуспешная проверка доступности по-прежнему учитываются.

Удалена панель «Роботы в работе» с фильтрами и её фоновая офлайн-загрузка.
Поиск по номеру/VIN и проверка выбранного робота остаются.

Внешний Inventory проверяет доступность сервера короткой одиночной пробой,
не создавая одновременную волну одинаковых сетевых ожиданий. Inventory остаётся
необязательной интеграцией для будущих функций: его статус показывается отдельно
и не блокирует общую готовность Tracker/Emergency.

Проверки исходников и итог живого нагрузочного прогона фиксируются в verification.json
релиза. Это тестовый кандидат: 700 роботов на карте и 200+ физических клиентов
требуют отдельной приёмки, её прохождение этот релиз не заявляет.

После временной ошибки при первом открытии робота страница сама повторяет
загрузку с ограниченной задержкой. Ошибки доступа и отсутствующий робот
не создают бесконечных повторов. Статус обновления Mac согласован с
последним результатом проверки и системного установщика.

Исправлена воспроизводимая гонка при передаче готового результата: следующий
запрос больше не закрывает WSS из-за ещё не завершившегося callback отправки.
Параллельные чтения Mac увеличены до 8 от питания и 4 на батарее с учётом
нагрузки. Брокер обрабатывает ответы отдельно от чтения heartbeat; истечение
срока отдельного запроса не закрывает весь канал. Проверки прав сохраняются.

HTML-ответ 404 от недоступного туннеля больше не означает отсутствие робота:
интерфейс показывает временную недоступность сервиса и повторяет чтение.
Настоящий JSON-ответ API 404 и ответы проверки прав сохраняют свой смысл.
Нативный Mac также не засчитывает HTML-страницу Tuna как успешную связь:
статус остаётся offline, дата последнего успеха и сессия владельца сохраняются.

На момент сборки Khadas TEST недоступен по HTTP и SSH после запуска OTA RC24.
Причина и результат серверной установки ещё не подтверждены. Это блокирует
повторную живую проверку 60 роботов за 5 минут; сборочные тесты её не заменяют.
