# Robopark 0.2.3-rc.17 — Mac recovery and offline workspace

Тестовый prerelease; production и Latest stable 0.2.2 не обновляются.

RC16 отозвана до установки из-за пропущенной совместимости с RC15. Этот
выпуск включает её исправления и явно разрешает переход с RC15. Сборщик
требует `--from-version` и проверяет совместимость до упаковки.

После «Подготовить офлайн» страница «Роботы» показывает сохранённый список
роботов выбранного парка. Раньше данные сохранялись, но компонент реестра не
был подключён к странице. Поиск по номеру и переход к карточке сохранены.
Подготовка покрывает начальный список без фильтров; свежая телеметрия требует
связи с корпоративным ресурсом. При таймауте сервера сохранённый список остаётся
видимым с предупреждением, даже когда браузер считает сеть доступной.
Подтверждённый отказ в доступе не заменяется старым снимком.

При временной недоступности серверного Inventory повторные запросы используют
разрешённый Mac без повторного ожидания сетевого таймаута сервера. Серверный
доступ проверяется снова после короткого интервала; после восстановления
возвращается обычный server-first путь. Права владельца и отказы авторизации
сохраняются. Это устраняет задержку около 10 секунд перед каждым резервным
чтением, обнаруженную при живой проверке RC15.

Локальный HTTP-сервис Mac резервирует место для файлов интерфейса и служебных
запросов отдельно от медленных запросов к серверу. При обрыве внешней связи
загрузка страниц и переходы по приложению не должны терять JS/CSS из-за
занятых соединений. Общие ограничения соединений, памяти и времени сохраняются.

Серверный OTA и автоматическое обновление Mac сохраняют существующие настройки
TEST, аккаунт и корпоративную сессию. Наличие пакета не означает, что новая
версия уже установлена: результаты сборочных тестов и живой приёмки фиксируются
отдельно.

После потери связи Mac прекращает считать канал готовым по истечении срока
ожидания heartbeat и переподключается, даже если системный WebSocket не
завершил ожидающее чтение после отмены. Подтверждённые heartbeat сохраняют
здоровое простаивающее соединение. Поздние ответы старого соединения не
изменяют новое.

Живые чтения роботов выполняются только без записи. Успешная сборка не
подтверждает устойчивую работу корпоративных ресурсов или физическую
производительность при 200 пользователях; это отдельная приёмка.
