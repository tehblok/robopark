# Единый поиск задач робота: сайт и Telegram

Проверка 2026-10-08. Причина потерь: отдельный Telegram-фильтр требовал
парковый тег на каждой задаче; related-панель сайта дополнительно допускала
только repair. Сервисные кампании с тегом SC и обычным приоритетом терялись.

Теперь related-панель, быстрый поиск сайта и Telegram open/history получают
задачи из tracker_robot_search. Он использует общий tracker_cache и полную
свежую выборку реестра, если она доступна. Авторизация проверяется на каждом
запросе, включая попадание в кэш. Telegram только преобразует DTO для
прежнего оформления сообщений.

Ремонт, обслуживание и калибровка доступны независимо от приоритета.
Задача без известного паркового тега допускается при открытой задаче того же
точного робота и той же очереди в доступном парке. Чужой известный парк
не переопределяется этим правилом. Скрытая задача не служит подтверждением.
Карточка, комментарии и лента имеют такой же read scope; права изменений
остаются прежними. Для многозначного rover чтение проверяет принадлежность
одним ограниченным запросом, а не последовательным запросом на каждого робота.

Поле rover сохраняется массивом; холодный поиск учитывает a/A, кириллическую
а и полный YASADR. При копировании общего кэша удаляется SDK resource,
содержащий соединения/блокировки. Копия не изменяет исходный кэш.
Закрытая web-вкладка ограничивает Tracker-поиск 14 днями и повторно проверяет
точную границу локально. Старое сопоставление padded Summary сохранено.

До установки на живом Tracker в отдельном процессе проверен пример с одним
парковым ремонтом и двумя сервисными задачами SC: web и bot вернули одинаковые
три ключа. Первый запрос — 3,948 с, второй через общий кэш — 0,021 с.
Тестовые сообщения в Telegram не отправлялись.

Отдельно проверены выборки PNG всех 12 действующих парков: donor присутствует
в каждом, truncated=false. История SLA и оформление отчётов не менялись.

Проверки: регрессии общего поиска, доступа, карточки/ленты, кэша и пагинации;
web IssueWorkbench — 141 тест; штатный бот — 115 тестов; fast gate;
production web build; 26 проверок версии, совместимости и миграций.
Полный API suite: 3037 passed, 37 skipped, 3 failed. Две причины — устаревший
ожидаемый Alembic head и mock старого пути поиска — исправлены, оба файла
перепроверены: 11 passed. Проверка бюджета загрузки истории не уложилась
в секунду под полным прогоном; отдельно прошла за 0,91 с, затем прошла
в составе 189 проверок SLA, истории, operations и tracker_read.
Полный suite повторно не запускался; три исходных сбоя не скрываются.
