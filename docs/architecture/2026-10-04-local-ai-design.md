# Локальный помощник Robopark на AGX Orin

## Цель и согласованные ограничения

Владелец поручил 4 октября 2026 автономно реализовать готовую подсистему для механиков, операторов и администраторов: локальный чат с источниками, встроенную пополняемую базу знаний, интерфейс, промпты, подключения к API и управляемые скрипты/автоматизации. Предпочтительная модель — prism-ml/Ternary-Bonsai-2-27B-gguf. Установка, загрузка и исполнение ИИ допустимы только на подтверждённом NVIDIA AGX Orin с NVMe. Khadas продолжает обычную работу без ИИ. Формат OTA v1 сохраняется, восьмичасовой тест исключён. Пользователь уходит и явно поручает самостоятельно принимать реализационные решения; повторные этапы согласования не требуются.

## Архитектура

1. Хост устанавливает закреплённый PrismML llama.cpp и PQ2_0 на NVMe. Нативная сборка использует установленный CUDA toolkit, SM87, отдельную службу и лимиты памяти. Модель недоступна из сети: localhost сервер и частный Unix broker для контейнеров API/worker. Установка запускается отдельно от обязательных служб сайта; сбой ИИ не останавливает Robopark. Никакой автоматической замены BSP/JetPack.
2. API хранит документы, поисковый индекс, беседы, фоновые задания, подключения, версии скриптов и правила в существующей БД. Обычная миграция добавляет таблицы; секреты подключений шифруются существующим ключом приложения. Статус ИИ доступен отдельно от его готовности. Выключение блокирует новые задания и останавливает inference; удаление весов не удаляет знания.
3. Один последовательный фоновой исполнитель обрабатывает генерацию и правила. LLM не имеет доступа к произвольным URL, секретам, shell или инструментам от имени пользователя. Сначала выдаёт ответ/проект; администратор отдельно сохраняет и включает конкретную автоматизацию. Ошибки модели/структурного вывода видны в журнале, никогда не становятся командами.
4. RAG использует ограниченный поиск по индексированным словам с русской нормализацией. Выбираются только доступные текущему пользователю документы его парка и общие активные инструкции; источник, тип достоверности и выдержка возвращаются вместе с ответом. История чата принадлежит пользователю, доступ к парку повторно проверяется при чтении и выполнении. Неизвестные ссылки модели не считаются подтверждёнными источниками.
5. Начальный импорт: воспроизводимый локальный конвертер PDF/Markdown/Telegram JSON/тикетов создаёт приватный пакет JSONL. Исходные экспорты, токены и персональные контакты не попадают в Git/OTA. Пакет импортируется на AGX через интерфейс; по умолчанию материалы остаются кандидатами. Отдельными флажками можно активировать инструкции и разрешить использование тикетов, заметок и чатов как непроверенного опыта. Повторный импорт идемпотентен.
6. Самопополнение: после подтверждённого закрытия ремонта сохраняется ограниченная запись из проверенного структурированного отчёта, с компонентами/дефектом/действием, привязкой к парку и циклу. Это наблюдение, не нормативная инструкция. Источники можно редактировать, отклонять, выключать, удалять; удалённое не возвращается очередным сканированием.
7. Автоматизации реагируют на подтверждённое закрытие тикета и фильтры детали/дефекта/слов. Черновик, включение, выключение, удаление, пробный прогон, журнал и очистка доступны в интерфейсе. Каждая пара событие/правило уникальна; внешние неопределённые результаты не повторяются автоматически. Изменение правила отключает его до нового включения.
8. Подключения API задают фиксированный HTTPS домен и путь (допустима только подстановка ключа тикета в пути), метод и шаблон тела администратором. Секрет не поступает модели; запрет redirects, ограничение ответа, DNS/IP-проверка, idempotency key. Генерируемый Python-скрипт работает только в одноразовом контейнере без сети/секретов/host mounts, non-root, read-only FS, с лимитом времени/памяти/процессов. Результат JSON может использоваться как параметры заранее настроенного подключения. Активация требует успешной пробы актуальной версии скрипта.

## Интерфейс и API

Раздел `/assistant`: вкладки Помощник, База знаний; для admin/royal — Автоматизации, Скрипты, Подключения, Настройки/журнал. На неподдерживаемом хосте короткое объяснение и статус, без загрузки моделей и активных действий. Из тикета — переход к помощнику с issue_key/park. Сообщения идут через постоянные задания с polling/cancel; ошибка сохраняет введённый текст, отправка идемпотентна.

API под `/ai`: status, config, prompts, documents (search/import/edit/delete), conversations/messages, jobs/cancel, connectors, scripts/test, automations/preview, runs/purge. Детали контракта фиксируются в плане и Pydantic-схемах до реализации UI. Чтение и управление ограничены ролями и парками; disabled/unsupported возвращает явную причину, без вызова runtime.

## Ограничения и критерии приёмки

Никакого заявления о реальном throughput/качестве без запуска на GEACX1. На текущем Mac/Khadas проверяются контракты, миграции, RAG, права, очереди, автоматизации и интерфейс с тестовым inference; физическая CUDA-проверка выполняется установщиком на AGX и нужна перед пометкой ready. Отсутствие CUDA/NVMe/модели не включает software fallback на Khadas. Проверить межпарковую изоляцию, отозванные права, prompt injection в источниках, повтор импорта/события, выключение/удаление в очереди, таймауты, перезагрузку, OTA и восстановление.
