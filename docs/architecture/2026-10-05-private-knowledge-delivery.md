# Полная база знаний при установке

Владелец выбрал зашифрованную публикацию полных исходников в публичном GitHub,
с одним вводом ключа на новом AGX. Исходные чаты, тикеты, инструкции, фотографии,
таблицы, приватная подготовленная база и карта происхождения доставляются вместе.
Секретные OAuth хранилища ноутбука в поставку не входят.

## Контракт поставки

Проект и очищенная общедоступная база остаются в Git. Большие приватные данные —
отдельные age X25519 архивы в GitHub Release. Каждая часть самостоятельно
зашифрована и содержит tar.gz с внутренней описью SHA-256. Публичный
`deploy/knowledge/manifest.json` закрепляет версию, URL, размеры и хэши ciphertext;
он не содержит имён исходников. Изменение manifest выпускает новую версию
корпуса, а не переиспользует опубликованные имена assets.

Установщик проверяет физический AGX Orin и управляемое хранилище. На остальных
хостах нет скачивания модели, корпуса или запроса ключа. AGX с недоступным NVMe
останавливает установку корпуса: подмена выбранной базы общедоступной недопустима.

Входящие файлы не исполняются. В частности, старые скрипты и skills — архивные
источники, а не автоматически разрешённые инструменты помощника.

## Загрузка и хранение

Загрузчик использует HTTPS, Range, фиксированные размеры и SHA-256. Частичная
загрузка остаётся для повторного запуска. Ключ вводится скрыто после загрузки,
передаётся age через временный файл 0600 в `/run` и удаляется после операции;
ключа нет в аргументах, журнале или конфигурации приложения.

Штатный age 1.3.2 linux-arm64 скачивается по закреплённому хэшу официального
дистрибутива. Каждая часть полностью аутентифицируется перед распаковкой.
Распаковщик допускает только обычные файлы из внутренней описи, ограничивает
размеры и количество, отклоняет links, traversal, дубликаты и несовпадения хэшей.
Весь корпус публикуется атомарной сменой `knowledge/current` только после
проверки всех частей. При ошибке прежняя версия остаётся текущей.

Данные находятся в `/var/lib/robopark/knowledge/versions`, вне immutable release
и OTA retention. Это NVMe в обоих поддерживаемых storage layouts. Исходники
доступны только root; в API/worker монтируется только `current/bundle`, read-only.
Временные plaintext-части удаляются, ciphertext-кэш — после успешной установки.
Предыдущие версии корпуса автоматически не удаляются.

## Преемственность знаний

Импортируется ровно один выбранный пакет. `repair-private-v2` включает все
идентификаторы текущего `repair-public-v1`. Их тексты могут стать полнее, но
записи сохраняют прежние receipts. Остальные записи имеют namespace
`private:repair-v2`. Префикс `public:` обозначает происхождение идентификатора,
а не гарантию публичности текста в установленном полном пакете.

Правки, смена статуса и удаления пользователем не отменяются импортом.
Переход не меняет схему БД. Тип manual сохраняет instruction; исторические
тикеты, чаты и заметки остаются unverified. Упоминание закрытия задачи не является
подтверждением результата ремонта. Данные v1 хранятся для воспроизводимости,
но повторно не импортируются.

Исчезновение выбранного mount является ошибкой. OTA продолжает монтировать
установленный корпус; миграции работают без необязательного mount. Для новой
версии корпуса ключ потребуется снова: он не хранится на хосте. Обычное OTA
обновление кода повторного ввода не требует.

## Пределы результата

Очистка, целостность и корректный импорт не доказывают правильность каждого
совета. Независимая приёмка ответов Bonsai/CUDA на физическом GEACX1 ещё нужна.
Фото сохраняются, но OCR/vision по ним не выполнялся. Недоступные в исходной
выгрузке вложения остаются явно учтёнными пропусками.
