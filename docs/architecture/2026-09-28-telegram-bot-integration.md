# Telegram-бот как управляемый сервис Robopark

## Цель и границы

Сохранить существующего Telegram-бота, его подписчиков, сценарии поиска роботов,
отчёты и администрирование, но запускать его как отдельный отключаемый сервис
Robopark. Владелец (`royal`) управляет токеном, импортом данных и полным
включением/отключением в веб-интерфейсе. Telegram-админка остаётся для
операционных действий; опасные host/OTA-действия должны проходить через
контролируемый механизм Robopark. Бот не хранит Tracker-токен и не ходит в
Tracker напрямую: все запросы идут через внутренний API Robopark, который
использует существующую интеграцию Tracker.

Это отдельная подсистема, которую можно будет удалить без миграции основных
таблиц задач. Активные данные бота живут в выделенном каталоге data-volume;
копии Robopark включают этот каталог. Отключение не удаляет данные.

## Изученные входные данные

- `tracker-report-armbian-20260928.tar.gz` и рабочий ZIP содержат одинаковые
  байты 140 общих файлов кода. ZIP содержит дополнительно восемь JSON-файлов
  данных (локации, роли, пользователи, рассылки, расписания и sidecar).
- Экспорт не содержит Telegram-токена и других секретов. Их владелец вводит
  заново через Robopark; Tracker-токен уже хранится в Robopark.
- Экспорт не содержит `sk_campaigns.json`, offset Telegram и некоторые
  служебные файлы. Невозможно восстановить неэкспортированные состояния;
  исходный ZIP сохраняется неизменным для повторной проверки.
- Telegram ID не имеют доказанной связи с user ID Robopark. Старые роли
  сохраняются; владелец связывает учётные записи вручную.

## Рассмотренные варианты

1. **Изолированный переходный сервис — выбран.** Перенести работающий код бота
   в отдельный образ, заменить доступ к Tracker внутренним API, а lifecycle
   передать Robopark. Это сохраняет поведение и позволяет затем переносить
   функции по одной без повторного импорта данных.
2. Переписать весь бот сразу поверх worker Robopark. Меньше старого кода, но
   высок риск потери редко используемых сценариев и требует повторной
   приёмки всех Telegram flows до первого запуска.
3. Оставить отдельную установку на хосте. Нельзя надёжно управлять ей через
   Robopark и единообразно обновлять/сохранять данные.

## Устройство

- Compose-сервис `bot` строится отдельно и по умолчанию не запускается.
  Его процесс не получает Docker socket, host-root или Tracker-токен.
- Внутренний API предоставляет боту только ограниченные операции чтения
  Tracker, необходимые четырём методам существующего `tracker_api`:
  `search_issues`, `get_issue`, `get_issue_links`, `get_status_changelog`.
  Общий Tracker token остаётся в `platform_settings` API. Запросы бота
  аутентифицируются отдельным host-generated service key, доступным только
  API и bot; ключ не отдаётся в веб-интерфейс и не попадает в архивы.
  Область чтения ограничена очередями активных парков и отдельным списком
  дополнительных очередей, который задаёт только владелец. Ошибка или
  небезопасное состояние этого списка блокирует обращение к Tracker.
- Telegram token хранится зашифрованным в `platform_settings` и выдаётся
  только bot-сервису через внутренний API. Смена токена требует выключения
  бота. API различает `stopped`, `starting`, `running` и `unavailable` по
  желаемому состоянию и приватному heartbeat процесса. Heartbeat показывает
  жизнь процесса, но не доказывает доставку сообщений Telegram.
- Royal меняет устойчивый флаг запуска; выделенный systemd path/helper
  выполняет только точные Compose-действия для `bot`.
  Выключение останавливает dispatcher и все плановые отправки, но оставляет
  каталог данных и Telegram token. При загрузке и OTA восстанавливается
  сохранённое `enabled`-состояние; rollback возвращает совместимый образ.
- Интерфейс владельца показывает желаемое и наблюдаемое состояние, маскированный
  токен, preview импорта и общие настройки. Telegram-админка продолжает
  операционные функции; её host/OTA-действия не исполняют старые shell-скрипты.
  Проверка фактической доставки и полный перенос host-действий ещё требуют
  приёмки на Linux ARM.

## Общие настройки сайта и Telegram

Веб-интерфейс `royal` и Telegram-админка используют один каталог настроек:
роли, пользователей, локации и чаты, расписание, текстовые и СК-кампании,
профиль prod/test и паузы. Сайт также задаёт дополнительные разрешённые
очереди Tracker. Записи сайта защищены ревизией (`If-Match`); структурные
файлы меняются только при выключенном боте. Профиль и паузы можно менять во
время работы, операции Telegram и сайта используют общий файловый lock.
Секреты вводятся только в веб-интерфейсе владельца и не пересылаются в чат.

Для частых операций сайт предоставляет именованные поля, время и переключатели;
сложные структуры пока доступны через проверяемый JSON-редактор. Это ещё не
полный визуальный паритет редакторов Telegram и сайта: добавление новых
локаций, ролей и кампаний на сайте требует расширенного редактора либо
Telegram-админки.

## Перенос данных и переход

Импорт ZIP работает только при выключенном боте. Preview перечисляет восемь
ожидаемых имён, размеры и SHA-256, без содержимого. Запись сохраняет исходные
байты JSON атомарно в `data/telegram-bot/data`; существующие файлы никогда
не перезаписываются неявно. Текущий экспорт хранится вне git и не входит в
установочный архив. Для восстановления полного состояния после аварии нужен
snapshot Robopark вместе с этим каталогом.

Перед первым запуском нового сервиса прежний `tracker-dispatcher` и его
таймеры на хосте должны быть остановлены: одновременно использовать один
Telegram token для двух `getUpdates` нельзя. Новая служба продолжает
получение неподтверждённых Telegram updates и сохраняет offset в собственных
данных; отсутствие offset в ZIP отмечается в экране перехода.

## Проверки и запреты

- Сначала короткие падающие тесты для импорта, owner-only API,
  enable/disable/reboot/OTA/rollback и внутреннего Tracker gateway.
- Затем короткие интеграционные тесты поиска робота, рассылки PNG,
  расписаний/ролей, повторного запуска, ошибки Telegram/Tracker и
  сохранности данных при выключении.
- Перед заявлением готовности нужен визуальный проход web-экрана владельца,
  реальный Telegram тест с остановленным старым процессом и ARM-стенд.
- Не копировать токены/персональные JSON в git, фикстуры, логи и
  установочный архив. Не удалять старую установку или данные без точного
  предпросмотра и разрешения владельца.
