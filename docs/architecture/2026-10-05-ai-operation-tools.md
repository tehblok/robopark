# Действия локального помощника

Статус: реализация по запросу владельца. Принятое правило: обычные операции автоматически в пределах роли; закрытие задачи и удаление скрипта только после подтверждения конкретного действия.

## Границы

Функции доступны только установленному локальному помощнику на подтверждённом AGX Orin. Khadas сохраняет основную систему без запуска ИИ. Модель выбирает только именованные инструменты через нативный function calling; JSON из обычного ответа никогда не исполняется. Один вызов за ход, не более шести действий на сообщение. Нельзя управлять движением робота, открывать root-терминал или обходить фотоотчёт и проверку ремонта.

Каталог: получение задачи и доступных полей ремонта, взятие в работу, комментарий, передача, подтверждённое закрытие через штатную проверку оператора; получение показаний/ошибок робота; список, чтение, создание, изменение, включение, отключение, тест, запуск и подтверждённое удаление скрипта. Скрипты доступны только администраторам/royal, исполняются существующим sandbox без сети, файлов хоста и секретов. Включение требует проверки текущей ревизии.

## Протокол

Существующий текстовый API сохраняется. Обновлённый интерфейс отправляет use_tools=true. Сервер формирует каталог для роли и повторяет проверки перед каждым действием. Объект AIAction хранит канонические аргументы, снимок целевой ревизии, состояние, результат и стабильный ключ повторного запроса. Модель не получает инструмент подтверждения. UI подтверждает digest конкретного action; подтверждение действует 15 минут и не переносится на другие аргументы/ревизии.

Внешний вызов начинается только после сохранения running. Перезапуск помечает такой незавершённый вызов uncertain, не повторяет его. Уже выполненные шаги остаются видны, даже если последующий ответ модели не удался. Удаление разговора/отмена отклоняются во время выполняющегося действия; ожидающие действия отменяются. Пока разговор сохранён, квитанции хранятся вместе с его историей: они нужны для повторной проверки доступа к данным ответа. После удаления разговора оставшиеся квитанции очищаются через 30 дней. Очистка истории доступна администратору.

Контекст учитывает схемы инструментов, аргументы и результаты; одна системная инструкция, правильные пары assistant/tool, ограниченный размер ответов. Источники и ответы сервисов остаются недоверенными данными. Проверки прав повторяются при чтении сохранённых результатов.

## Реализация и проверка

1. Нативный транспорт runtime/broker: строгая валидация, tool-aware token count, регрессии malformed/parallel/dangling calls.
2. Общие операции предметной области с сохранением RBAC, scope, lease, idempotency, outbox и аудита.
3. Аддитивная миграция квитанций, ограниченный исполнитель, подтверждение, отмена, восстановление и очистка.
4. Карточки действий и подтверждение в чате; защита от поздних ответов другого разговора.
5. Проверки реальных эффектов: нельзя выполнить закрытие/удаление без подтверждения; повтор не дублирует; смена роли/парка/ревизии блокирует; перезапуск не повторяет сомнительный вызов. API/host/web проверки и независимое ревью.

Аппаратный прогон Bonsai/CUDA на AGX выполняется после миграции на устройство. Успех программных тестов не заменяет эту проверку.
