# Живая карта и нагрузка парка

Статус: требования и проектное решение, 17.10.2026. Карта ещё не реализована.

Пользователь уточнил: внешний SDC Inventory пока не участвует в работе,
понадобится позже. Его отдельный статус не должен делать обязательные
Tracker/Emergency недоступными. Локальный склад Robopark — другой модуль.

Следующая задача — карта примерно 700 роботов с обновлением близко к реальному
времени. Система должна сохранять режимы 0/1/20 Mac, работу единственного Mac
на батарее и поддержку 200+ пользователей. Наличие живого источника обязательно:
без доступа и сервера, и Mac можно показывать только последнее известное состояние.

## Сбор и распространение

Общий планировщик собирает состояние один раз для разрешённой области данных,
а не отдельно для каждого посетителя карты. Одинаковые чтения объединяются;
приоритет у видимой области и активных роботов. Ограниченная очередь, лимиты
источника, задержки ошибок и обратное давление сохраняются. Увеличение числа
пользователей не должно линейно увеличивать корпоративные запросы.

Для карты нужен короткий снимок: координаты, время измерения, доступность и
минимальные индикаторы. Полная диагностика Emergency загружается при открытии
карточки. Первичная загрузка получает снимок, далее подписка — только изменения
с последовательностью событий. После разрыва клиент получает пропущенные
изменения либо новый снимок. Клиент показывает возраст измерения и отдельно
состояние транспорта; старые координаты не обозначаются как живые.

Предпочтителен поддерживаемый корпоративным источником поток или пакетное API.
Если доступно только индивидуальное чтение, частота должна соответствовать его
лимитам: при существующем бюджете Emergency 8 чтений/с полный обход 700 роботов
занимает минимум 87,5 с даже без задержек. Поэтому обещать обновление всех 700
каждые несколько секунд на текущем API нельзя. Нужны проверка контракта источника,
согласованный бюджет и отдельное испытание; ограничения не снимаются вслепую.

Сервер координирует маршруты по доступности конкретного ресурса. Mac использует
сессию своего владельца; совместный кэш и подписки разделены по области доступа.
Политика операторов/механиков, отзыв доступа и права на роботов сохраняются.
Inventory подключается по реальной потребности, не участвует в горячем цикле карты.

## Приёмка

Текущий этап: 60 реальных роботов, 5 минут, автоматические повторные чтения;
считать долю успешных ответов, возраст данных, задержки p50/p95/p99,
восстановление канала, длину очереди и корпоративные вызовы. Только чтение.

Будущий отдельный этап: 700 роботов и 200+ подписчиков, 0/1/20 Mac,
потеря источника, переподключение, медленный клиент, батарея и ограниченная сеть.
Измерять трафик Wi-Fi сервера и границы памяти очередей. Успешные 60 роботов
не являются подтверждением этой будущей мощности. Чувствительная телеметрия и
координаты остаются в локальных QA-артефактах, в релиз идут только агрегаты.
