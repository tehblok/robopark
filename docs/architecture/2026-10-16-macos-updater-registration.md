# Перерегистрация macOS updater после замены пакета

Проверено 16.10.2026. Область: тестовый Mac installer; production не меняется.
Постоянный фикс реализован в тестовой ветке после RC14; в опубликованный
RC14 он не входит. Живая проверка self-update нового пакета ещё требуется.

## Подтверждённая причина

После автоматической установки RC13 исполняемый файл updater прошёл проверку
подписи, но запуск его LaunchDaemon завершался `EX_CONFIG (78)` до выполнения
кода. Журнал macOS сообщил, что загруженный job ссылается на отсутствующую
регистрацию BTM при обновлении LWCR. Установка пакета создала новую регистрацию;
загруженный job сохранил предыдущую. Один `launchctl bootstrap` существующего
job не обновляет её. Подавление этой ошибки скрывало неисправность.

## Порядок исправления

Перерегистрация должна происходить после выхода установщика и updater.
`bootout` родительского updater прямо из `postinstall` может прервать ещё
работающую установку. Поэтому пакет запускает отдельный фиксированный root job
с отдельным процессом, который переживает завершение установщика.

Этот job получает ту же kernel-блокировку `update.lock`, которую updater
держит на всём протяжении обновления. Он ждёт завершения установщика и
освобождения lifecycle/install блокировок, выполняет `bootout` под kernel lock,
затем освобождает lock и выполняет `bootstrap` уже отсутствующего job.
Запущенный таймером старый helper не может начать работу без этого lock.
Живой тест macOS подтвердил: `launchctl disable` не является такой защитой —
уже загруженный job продолжает старты по StartInterval. Использовать его
как замену kernel lock нельзя.
Состояние отключённого пользователем автозапуска сохраняется. Наличие маркера
удаления останавливает перерегистрацию. Ошибки и ограничение времени ожидания
должны оставаться диагностируемыми; нельзя маскировать их как успешную установку.

Служба принимает только фиксированные пути Robopark и не исполняет переданные
пользователем команды. Её файлы устанавливаются пакетом с владельцем root и без
права изменения обычным пользователем. Удаление Robopark убирает и эту службу.

## Проверка результата

Успешная команда `bootstrap` подтверждает регистрацию, но не успешный запуск
updater. Живая проверка требует нового `checked_at` в status.json, завершения
процесса и ожидаемых installed_version/status. Старый `current` или `failed`
не является результатом нового запуска.

Тесты проверяют ожидание установщика и updater, сериализацию работы через kernel lock,
отключённую службу, удаление, таймаут и ошибки launchctl. Отдельно проверяется
автоматическое обновление установленного приложения. Синтетические тесты не
заменяют проверку BTM/LWCR на конкретной версии macOS.

Для уже сломанной регистрации RC13 подготовлено одноразовое восстановление:
штатный администратор Mac запускает проверенный локальный скрипт, который
перерегистрирует idle updater, ждёт установки RC14 и повторяет регистрацию
после замены пакета. Пароль администратора не хранится и в приложение не
передаётся. Это не обход авторизации macOS.

Локальные проверки: AgentCoreChecks 265 PASS; host package/command/uninstall/registration 38 PASS; native updater build PASS. Отдельный живой тест macOS на временной службе подтвердил общий flock и запуск после release/bootstrap. Временные службы удалены.
