Исходная база этого раздела: 326964e (0.1.42). Текущий `VERSION`: 0.1.45.

Независимые ai/codex-platform и ai/vscode-product-ui не объединяются до передачи их результатов.

## Выполнение и критерии приёмки

- [ ] Задачи: проверить реальный API-цикл механик → сменщик → проверка → оператор; закрытый статус имеет приоритет над локальным владельцем. Проверить сообщения, повторную отправку, обязательный комментарий и фото.
- [ ] Завершение ремонта: понятная форма с сохранением ввода при ошибке, причиной отказа, возможностью отмены и отдельными выбором файла/камерой. Возврат оператором через встроенную форму вместо браузерного prompt.
- [ ] Запчасти в задаче: видны отсутствующие позиции, поиск по названию/артикулу, явное подтверждение успешного списания; повторная загрузка остатков не должна повторно списывать деталь. Защитить повторные нажатия и смену задачи.
- [ ] Проверка: регрессионные API и web-тесты, сквозные браузерные сценарии, сборка и проверка мобильных ширин. Фиксировать ограничения стенда отдельно от ошибок приложения.
- [ ] Передача: описать изменения, тесты, риски и пересечение файлов с аудитами. Не публиковать релиз как «полностью проверенный» без проверки установки на целевом устройстве.

## Исходные наблюдения

- TaskPartsPanel запрашивает только in_stock и удаляет нулевые позиции из результата.
- SubmitReviewForm скрывает конкретную причину отказа за общим сообщением.
- Возврат с проверки в IssueWorkbench использует window.prompt.
- В workflow закрытый статус может быть перезаписан in_progress при наличии локального claim без review; нужны воспроизводящий тест и проверка реальных потребителей.

## Проверки и оставшаяся работа

### Исправлено в коде

- Закрытый статус Tracker больше не перекрывается локальным владельцем; повторное взятие закрытой задачи отклоняется.
- Отложенные start/return/review проверяют свежий закрытый статус перед записью и не открывают закрытую извне задачу повторно.
- Локальное принятие оператором больше не выдаётся за подтверждённое закрытие Tracker. До получения закрытого статуса отображается «Закрытие не подтверждено».
- Ревью: claim читает свежий Tracker, а не 30-секундный кэш; при недоступности чтения новый claim не создаётся. Незавершённое/неудачное закрытие блокирует новое взятие. При новом цикле после успешной доставки закрытия прежний closed-review не блокирует действия механика.
- В workflow добавлен безопасный код причины рассинхронизации (только разрешённые значения); интерфейс объясняет отсутствие перехода/прав/предыдущую ошибку.
- Начало SLA берётся из истории очереди, не из времени создания тикета.
- Форма передачи на проверку блокирует повторную отправку и изменение полей во время запроса, сохраняет ввод при ошибке, показывает причину и позволяет отмену.
- Возврат оператором — встроенная форма вместо window.prompt, с обязательной причиной и сохранением ввода при ошибке.
- В списании есть серверный поиск по названию/артикулу, видны отсутствующие позиции. Подтверждённое списание и ошибка обновления остатков разделены; повтор загрузки не списывает повторно. Запросы и выбор изолированы между задачами.
- «Мои задачи» в мобильной навигации — читаемый шрифт 14px вместо 12px.
- Открытие формы передачи/возврата не показывает ложное подтверждение выполненного действия.
