# Передача изменений product-completion

База: `326964e`, версия 0.1.42. Независимые ветки аудитов не объединялись.

## Область изменений

- API: `task_lifecycle.py`, `tracker_actions.py`, `tracker_outbox.py`, `schemas.py`, тесты жизненного цикла и отложенных действий.
- Web: IssueWorkbench, формы передачи/возврата, TaskSyncStatus, TaskPartsPanel, мобильная навигация; связанные тесты.
- IssueActionsPanel: открытие формы не означает выполненное действие. browser_diagnostic_bridge: имитация отказа Tracker распространяется и на чтение тикета.
- Контракт: новый `workflow.display_status=closing`, необязательный `sync_error_code`. Без миграции БД. API и web выпускать вместе; старый клиент не знает подпись нового статуса.
- Права, токены, настройки Tracker, независимые аудиты и установщик не менялись.

## При объединении

Сохранить защиту доступа и существующие stable idempotency keys из обеих веток. Не возвращать `created` как начало SLA. Не смешивать подтверждение списания с успешностью загрузки остатка. Не заменять состояния ожидающего/неудачного закрытия на «Закрыта» до подтверждения Tracker.

Перед новым взятием задачи выполняется свежая проверка Tracker, а не чтение из 30-секундного кэша. Если Tracker недоступен, новый claim не создаётся. Это намеренное изменение: невозможно достоверно исключить внешнее закрытие по старому кэшу. Уже принятые действия сохраняют фоновые повторы после сбоев связи.

В E2E возврат теперь заполняет встроенную форму. После операторского принятия тест дожидается закрытия карточки перед повторным открытием: ранее гонка давала ложное падение мобильного сценария. Проверки результата и порядка сообщений сохранены.

Подробности живой проверки и незакрытые дефекты: `PROGRESS.md`. Этот пакет не является доказательством готовности всей системы или исправления отказа внешнего Tracker.
