# Mac 0.2.2-based test release Implementation Plan

> Execution: autonomous implementation requested by the user; no additional
> design approval gate. Independent workers own separate directories, root
> integrates and verifies. Use test-driven-development for behavioral changes.

**Goal:** Deliver a GitHub prerelease with simple automatically updated Mac
workspace, employee/device graph, improved pool scheduling and RC43 Khadas setup.

**Architecture:** Merge v0.2.2 resilience into the existing Mac branch. Keep
outgoing authenticated WSS, immutable device ownership and central writes.
Native Mac and server/pool work run independently against an additive protocol.

**Tech Stack:** Swift/Foundation/CryptoKit/LaunchAgent/LaunchDaemon; Python
FastAPI/SQLAlchemy/PostgreSQL; React/TypeScript; Python OTA/zipapp builder.

**Spec:** `docs/architecture/2026-10-14-macos-022-test.md`.

## Global constraints

- `0.2.3-rc.1`, test only, fixed `https://roboparktest.ru.tuna.am`.
- No changes to production installation, stable release or credentials.
- Retain offline data and authorization, signed profile/catalog verification.
- Bound all telemetry, stale status, concurrency and update downloads.
- Root helper accepts no arbitrary user command, package path or origin.

## Review focus

- First login/reinstall/account switch cannot reassign another employee's key.
- Sleep/loss of corporate SSO and saturated Mac remove eligibility promptly.
- Automatic update cannot downgrade or install an unverified/cross-origin pkg.
- Autostart off survives pkg upgrade without terminating current work.
- RC43 journals/queues/network recovery cannot restore production side effects.
