# Единый hash-only OTA-пакет Robopark

## Цель

Заменить текущую цепочку Ed25519/GitHub Release одним локально собираемым
файлом `robopark-<version>.ota`. Один и тот же файл должен:

- устанавливать систему с нуля с USB;
- обновлять работающую систему через веб-интерфейс `royal`;
- выполнять диагностику и полное удаление;
- не зависеть от GitHub Actions, GitHub Releases и секретов подписи.

Первый переход выполняется только чистой переустановкой. Данные старой
системы не переносятся.

## Модель доверия

`royal` считается полностью доверенным инициатором системных операций. Из
продукта удаляются:

- закрытые и публичные ключи релиза;
- файлы `.sig`;
- ротация ключей и signing trust state;
- проверки Ed25519 в API, host agent и установщике;
- обязательная связь выпуска с GitHub.

Целостность обеспечивается SHA-256:

1. Сборщик включает в `manifest.json` размер и SHA-256 каждого payload-файла.
2. Браузер считает SHA-256 всего `.ota` до загрузки.
3. Сервер считает SHA-256 в процессе потоковой записи и сравнивает его с хэшем
   браузера.
4. Перед распаковкой API/host agent проверяет каждый payload-файл по манифесту.
5. Цельный SHA-256 пакета записывается в аудит и интерфейс `royal`.

Эта модель защищает от случайного повреждения при хранении и передаче, но не доказывает
авторство пакета. Целевая модель явно принимает этот риск.

## Формат `.ota`

`.ota` — детерминированное Python ZIP-приложение, совместимое с Python 3.10+:

```text
robopark-<version>.ota
├── __main__.py
├── manifest.json
├── installer/
│   ├── install.py
│   ├── diagnose.py
│   └── remove.py
├── release/
│   ├── apps/
│   ├── deploy/
│   ├── VERSION
│   └── release-metadata.json
└── checks/
    └── verify.py
```

Манифест содержит:

- версию формата;
- версию приложения и Git commit для аудита, но не для доверия;
- миграционную голову и список совместимых предыдущих версий;
- аппаратные и системные требования;
- описание изменений;
- список путей, размеров и SHA-256;
- лимиты распаковки.

Архив не содержит runtime-данных, `.env`, логов, кэша, дампов, резервных копий,
истории Git, node/python cache и артефактов предыдущих сборок.

## Локальное меню USB

Запуск:

```bash
sudo python3 robopark-<version>.ota
```

До любых изменений установщик показывает меню:

1. Чистая установка.
2. Обычное обновление.
3. Диагностика.
4. Полное удаление.
5. Выход.

Проверки окружения выполняются после выбора, чтобы ошибка не блокировала доступ к меню.

### Чистая установка

Поток:

1. Показ найденной старой версии и точного списка удаляемых каталогов/томов.
2. Ввод фразы `УДАЛИТЬ ВСЕ ДАННЫЕ`.
3. Ввод логина и дважды пароля первого `royal`.
4. Проверка хоста, целостности `.ota`, свободного места и Docker.
5. Остановка только Robopark-сервисов.
6. Безвозвратное удаление БД, вложений, отчетов, кэша, очередей, snapshots, старых
   релизов, конфигурации, signing state, Robopark Docker volumes и неиспользуемых
   Robopark-образов.
7. Установка нового runtime и создание пустой PostgreSQL.
8. Миграции, seed ролей/прав и создание первого `royal`.
9. Readiness/smoke-check. Пароль не попадает ни в лог, ни в shell history, ни в аргументы
   процесса.
10. Показ адреса, версии и результата.

Прежняя БД и файлы не резервируются и не восстанавливаются.

## OTA через сайт

OTA доступно только `royal` и работает как длительная типизированная операция:

1. Выбор одного `.ota` в браузере.
2. Локальное чтение манифеста, показ версии/изменений и вычисление SHA-256 в Web Worker.
3. Потоковая, возобновляемая загрузка с ограничением скорости и памяти.
4. Серверная проверка цельного хэша, манифеста, payload-хэшей, версии, миграций, лимитов и
   свободного места.
5. Явное подтверждение `royal` с повторной проверкой активной сессии.
6. Блокировка параллельных system operations и создание snapshot текущей версии.
7. Staging, миграции, cutover, readiness и smoke-check.
8. При успехе — атомарная публикация версии и аудит SHA-256.
9. При ошибке — автоматический откат приложения, БД и конфигурации.

Интерфейс не перезагружает страницу: прогресс и итог получаются из durable operation receipt. После
cutover PWA перезагружается один раз только при изменении build id.

## Версионность и хранение

- Понижение версии запрещено по умолчанию; `royal` может выбрать аварийный откат к последней
  локально сохранённой совместимой версии.
- Сервер хранит текущую и одну предыдущую версию. Staging и незавершённые upload-части удаляются по TTL.
- Пакет с уже известным SHA-256 не загружается повторно.
- Сборщик не включает в пакет его самого или предыдущие artifacts.

## Ошибки и восстановление

Публичные коды ошибок стабильны и не содержат секретов. Минимальный набор:

- `ota_invalid_container`;
- `ota_manifest_invalid`;
- `ota_hash_mismatch`;
- `ota_incompatible_version`;
- `ota_insufficient_space`;
- `ota_upload_interrupted`;
- `ota_operation_conflict`;
- `ota_migration_failed`;
- `ota_healthcheck_failed`;
- `ota_rollback_failed`;
- `clean_install_failed`.

После обрыва связи upload возобновляется по upload id и смещению. После перезапуска хоста durable
journal либо доводит операцию до безопасной фазы, либо откатывает её. Если автоматический откат не
удался, локальное USB-меню остаётся доступным.

## Локальная сборка

Единая команда создаёт один файл вне исходного дерева:

```bash
./scripts/build-ota.sh /absolute/output/directory
```

Сборщик:

1. проверяет чистоту tracked-файлов, `VERSION`, миграции и метаданные;
2. выполняет короткий обязательный release gate;
3. создаёт детерминированный `.ota`;
4. повторно открывает готовый файл независимым verifier и пересчитывает все хэши;
5. печатает путь, размер, SHA-256 и версию.

Долгие load/soak-тесты не запускаются сборщиком без явного флага и согласия.

## Изменение интерфейса `royal`

В разделе управления системой:

- одна зона «Обновление» с drag-and-drop/выбором `.ota`;
- версия, changes, SHA-256, размер и совмесимость после локального чтения;
- неблокирующий прогресс вычисления хэша и загрузки;
- кнопка «Установить» после проверки;
- дружелюбный этапный статус без технического лога;
- скачиваемая диагностика при ошибке;
- аудит инициатора, версии, SHA-256, времени и итога.

На телефоне upload можно свернуть; он продолжается в фоне при живой странице. При закрытии
страницы он возобновляется после повторного выбора того же файла.

## Проверки

Обязательные короткие проверки:

- детерминированная повторная сборка даёт идентичный SHA-256;
- изменённый байт, путь, размер, duplicate path, symlink, traversal и zip bomb отклоняются;
- браузер и сервер получают одинаковый SHA-256;
- потеря сети не теряет принятые upload-части;
- повтор команды не запускает вторую операцию;
- не-`royal` не может загружать, проверять и запускать OTA;
- обычный OTA сохраняет данные и откатывается при сбое;
- чистая установка действительно удаляет все Robopark-данные и создаёт первого `royal`;
- пароль `royal` не попадает в артефакт, лог и process list;
- проверка на Ubuntu 22.04+, Armbian и профилях 8/32/64 ГБ RAM.

Длительные load/soak-проверки остаются отдельными явными режимами и не запускаются без
согласия.

## Вне объёма

- Перенос данных из старой установки.
- Обратная совместимость со старыми `.zip`/`.tar.gz` релизами.
- GitHub Release как канал сборки или доставки.
- Криптографическое доказательство авторства артефакта.
