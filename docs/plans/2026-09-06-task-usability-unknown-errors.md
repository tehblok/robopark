# Карточка задачи и разбор неизвестных ошибок

Пользователь одобрил все шесть улучшений: мобильные действия, Markdown, черновики комментариев, время синхронизации, уведомления об изменениях и сбор неизвестных сигналов для разметки владельцем/администратором.

## Решение

- Карточка сохраняет контекст главного блокера и существующие вкладки. Действия остаются читаемыми на ширине 320 px.
- Markdown отображается через react-markdown без сырого HTML. Длинное описание раскрывается пользователем.
- Текст черновика хранится локально с ключом пользователя и задачи. Успешная отправка очищает отправленную версию; запоздавший ответ не удаляет новый текст. Файлы в хранилище не записываются.
- Время синхронизации относится к последнему успешному ответу API; оно сохраняется в кэше и не изменяется при ошибке. В карточке учитывается самый старый из ответов задачи и комментариев. Время исходной телеметрии остаётся отдельным показателем.
- Новые комментарии и изменения задачи видны в уведомлении. Переход к комментариям происходит только по нажатию, без автоматической прокрутки.
- Неизвестные диагностические события собираются после проверки доступа к роботу. Один стабильный сигнал объединяется между опросами и перемещениями в массиве. Наблюдения учитываются максимум раз в минуту на пару сигнал/робот.
- Администратор или владелец просматривает новый список, проверяет правило и назначает локализацию. Сохранение правила и связи с сигналом атомарно. Не соответствующее исходному примеру правило отклоняется. Проверяется также отсутствие неизвестного остатка при совместном применении каталога и нового правила. Повторное откладывание или открытие уже размеченной записи отклоняется при конфликте администраторов. Отложенные сигналы не скрываются в проверке робота.
- Сохраняются только ограниченные примеры сигнала; полные ответы внешнего сервиса не сохраняются. Миграция 0020 добавляет таблицы, 0021 — ограниченный исходный diagnostic unit отдельно от частично распознанного остатка. Полный snapshot не сохраняется. Старые записи получают исходный unit при следующей разрешённой проверке робота.

## Проверка и выпуск

Регрессии проверяются на уровнях API, React и браузера: роли и область доступа, дедупликация, конкурентная разметка, откат, реальные маршруты, безопасное отображение, сохранение черновиков, поздние ответы, обновления и мобильная вёрстка. Перед локальной миграцией сохраняется резервная копия SQLite. Затем полный набор API/web, сборка, lint, навигация, контраст и Chromium. Изменения остаются в текущей локальной ветке без push/merge.
