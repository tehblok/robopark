# Установка Robopark на Armbian и Ubuntu

Для новой установки используйте `robopark-<версия>-install.tar.gz` на Ubuntu 22.04+ или актуальном
Armbian, ARM64/AMD64, Python 3.10+. Номер ОС не зафиксирован: preflight проверяет
архитектуру, RAM, свободное место, systemd, Docker и доступные возможности.
Поддерживаются Ubuntu 22.04+ и Armbian на базе Ubuntu 22.04+ или Debian 12+;
остальные хосты отклоняются до распаковки. На пустой Ubuntu 22.04/24.04 или
Armbian с Debian 12/13 без Docker `.ota` подключает официальный apt-репозиторий
Docker и устанавливает Engine, Compose и Buildx. Для этого нужен доступ к
`download.docker.com` и apt-репозиториям ОС. На других поддерживаемых базах
Docker нужно подготовить заранее. Существующие Docker-данные и пакеты
установщик не удаляет.
Отсутствующий Tuna CLI устанавливается из официального apt-репозитория Tuna.
Ключи репозиториев сверяются с закреплёнными суммами: после их ротации нужен
новый проверенный пакет Robopark.

Свободное место (максимум из требования OTA, 6 ГБ и 15% раздела) проверяется
до распаковки на разделах релизов, данных Robopark, локального Docker
data-root и стандартного каталога `containerd`.
Если каталог `containerd` перенесён, отдельно проверьте его раздел.

```sh
mkdir robopark-install
tar -xzf robopark-<версия>-install.tar.gz -C robopark-install
cd robopark-install
sh INSTALL.sh
```

Скрипт проверяет `SHA256SUMS` и встроенный `.ota` до открытия меню. Отдельно
введите Tuna token скрытым вводом, полный публичный домен Tuna и пароль первого
royal. Не передавайте секреты в аргументах команд. Текущий архив содержит
`SOURCE-SNAPSHOT.json` с SHA-256 незакоммиченного рабочего дерева; этот снимок
предназначен для чистой установки и не переносит старую базу.

При наличии только `.ota` можно проверить и запустить его вручную:

```sh
python3 robopark-<версия>.ota verify --json
sudo python3 robopark-<версия>.ota
```

Меню показывается до любых проверок и предлагает чистую установку, обычное
обновление, диагностику, полное удаление и выход. Чистая установка требует
пустого хоста Robopark и откажет, если найдёт старые файлы, службы или том БД.
Для перехода со старой ветки сначала отдельно сохраните нужные данные;
если старую установку действительно нужно удалить, выберите «Полное удаление»,
проверьте точный список объектов и их объём, затем подтвердите фразой
`УДАЛИТЬ ВСЕ ДАННЫЕ`. Только после этого запускайте чистую установку.
Перенос данных и создание резервной копии автоматикой не выполняются.

После установки проверьте:

```sh
sudo python3 -I /opt/robopark/host-tools/robopark status
sudo python3 -I /opt/robopark/host-tools/robopark doctor
sudo systemctl is-active robopark.service robopark-tuna.service
sudo systemctl is-enabled robopark-backup.timer
curl -fsS http://127.0.0.1:8080/api/health/ready
```

Обычные последующие обновления выполняются тем же `.ota` с USB или royal на
странице «Система → Обновление». Они сохраняют данные, делают snapshot и
автоматически откатываются при ошибке. См. `docs/runbooks/`.

SHA-256 проверяет целостность, но не происхождение файла. Передавайте архив и
OTA только по доверенному локальному каналу. `SOURCE-SNAPSHOT.json` описывает
исходный снимок архива; он не требуется для исполнения отдельного `.ota`.
