Установка и обновление 0.2.0-rc.1 на Armbian/Debian/Ubuntu (ARM64/AMD64).
Целевые хосты: действующий Armbian 26 и новый Ubuntu 22.04 ARM64.
Установщик проверяет нужные возможности хоста, а не номер версии ОС.

1. Распакуйте архив в отдельную папку.
2. Перетащите START.sh в окно терминала и нажмите Enter.
3. Сначала выберите действие; затем введите пароль sudo и ответы установщика.

START.sh сам определяет ОС, архитектуру, состояние Robopark, установленную
версию и версию в архиве. Он сохраняет работающий Docker Compose либо устанавливает
недостающий, затем настраивает Tuna, Robopark, автозапуск, диагностику и обновления.

Просмотр состояния без изменений: ./START.sh status
Первая установка или меню обслуживания: ./START.sh
Обновление: ./START.sh update
Восстановление: ./START.sh repair
Переустановка системных файлов без удаления данных: ./START.sh reinstall
Удаление с сохранением данных: ./START.sh remove
Полное удаление: ./START.sh remove --purge-data
Полное удаление с последующей чистой установкой: ./START.sh clean-install

Обычное удаление не трогает базу и Docker-volume. Полное удаление требует
два точных подтверждения. Неявный откат на более старую версию запрещён.
Перед полной очисткой установщик проверяет вложенный релиз. Если проверка не
прошла, данные остаются на месте; после второго подтверждения очистка
необратима и установка начинается заново.

Обычный запуск: ./START.sh
После ошибки снова запустите тот же START.sh — незавершённый этап продолжится.

Для установки поверх имеющейся версии запустите ./START.sh: скрипт сам выберет
обновление или восстановление. Обновление сохранит базу, пользователей, настройки и Tuna.
Напрямую обновлять старые ветки, для которых релиз требует промежуточную версию, нельзя:
в этом случае установщик остановится до изменения данных.
Перед обновлением попросите пользователей сохранить черновики и закончить операции.
После обновления перезагрузите все вкладки сайта: старый интерфейс не умеет
передавать ревизию поставки и безопасно получит отказ вместо перезаписи данных.
При ошибке рабочая версия останется запущенной, а точная причина будет записана в
/var/log/robopark/ota-update.log (файл доступен только через sudo).

Расширенная проверка подлинности архива:

Сначала проверьте архив ДО распаковки и запуска install.sh.
Получите release-public-key.pem и verify-artifact.py отдельно из доверенного
checkout проекта. Не используйте ключ из ещё не проверенного архива.
На машине с Python 3.10+ и cryptography сохраните рядом все четыре файла:
robopark-installer-VERSION.tar.gz, .tar.gz.sig, .tar.gz.sha256, .tar.gz.json.
Без сетевого подключения выполните:
python3 verify-artifact.py --public-key release-public-key.pem robopark-installer-VERSION.tar.gz

После успешной проверки распакуйте архив в пустую папку и выполните:
sudo ./install.sh
Или для файла конфигурации с правами 0600:
sudo ./install.sh --non-interactive /защищённый/путь/install.conf
После прерывания: sudo ./install.sh --resume

Проверка подписи выполняется офлайн. Первоначальная установка требует сети
для системных пакетов, Docker-образов и Tuna. Секреты вводятся локально;
приватного ключа выпуска в комплекте нет. Вложенный ZIP не проходит повторную
криптографическую проверку. Архивы одинаковы для обеих поддерживаемых архитектур.
