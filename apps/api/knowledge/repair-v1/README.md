# Общая ремонтная база

Публичная производная выборка из предоставленных владельцем материалов:
4 706 записей — 9 текстовых инструкций, 1 318 справочных записей и неполных
инструкций, 3 379 структурированных ремонтных случаев. Сырые чаты, исходные
выгрузки, контакты, имена, служебные идентификаторы и карта исходников исключены.
Подозрительные шаблоны Tracker и длинные внутренние номера исключаются целиком
вместе с ремонтной карточкой. Служебные навыки и команды не импортируются.

`manifest.json` содержит размер, число записей и SHA256 `seed.jsonl`.
Только подтверждённый AGX при включённом ИИ подготавливает индекс; Khadas
этот пакет не импортирует. Worker обрабатывает небольшие порции, сохраняет
прогресс и защищает пользовательские правки и удаления при следующем OTA.

Историческое действие не подтверждает успешность ремонта. Неполные инструкции
сохраняют предупреждения о непрочитанных страницах и требуют оригинала.
Фотографии и отсутствующие вложения не восстановлены. Материалы не дают
помощнику полномочий выполнять действия. Подробности —
[в runbook](../../../../docs/runbooks/local-ai.md).

## Повторная подготовка владельцем

Исходники, приватный seed, отчёт со скрываемыми значениями и ключ идентичности
источников остаются вне Git. Для подготовки нужен актуальный приватный v2
и сохранённый 32-байтовый ключ. Команда из корня репозитория:

```bash
apps/api/.venv/bin/python scripts/build_public_knowledge.py \
  --input output/knowledge-seed-v2 --source-root 'Данные для базы' \
  --output output/knowledge-public \
  --private-report output/verification/public-knowledge/publication.private.json \
  --identity-key output/verification/public-knowledge/publication-identity.key
```

Перед копированием файлов в Git проведите независимую проверку готовой выборки:
редактор известных форматов не гарантирует обнаружения любых личных данных в
произвольном тексте. Публикуются только JSONL и manifest; приватный отчёт — 0600.

Ключ задаёт стабильные HMAC-ссылки и требует защищённой резервной копии вместе
с исходниками. Это не ключ подписи OTA. При отсутствии ключа команда завершается
ошибкой. `--initialize-key` существует только для первого создания нового набора;
для выпущенной базы нельзя менять ключ: SHA256-отпечаток сверяется с manifest
в Git. Сам ключ в manifest не содержится. Его потеря требует восстановления
резервной копии, иначе прежние удаления не могут быть сопоставлены с источниками.
